# 05. ブロック暗号からハッシュへ

> 親: [README](./README.md) ｜ 前: [04 モードと AEAD](./04_modes-and-aead.md) ｜ 次: [06 置換ベース暗号と未解決問題](./06_permutation-based-and-challenges.md) ｜ 層: 基礎(Layer 1)

ハッシュ関数は「任意長の入力を固定長に圧縮する」が、その内部は
**ブロック暗号の応用**として構成できる。歴史的に多くのハッシュ関数
（MD4, MD5, SHA-1, SHA-2）はこの方式で作られた。

**この1ページで分かること**

- 任意長の入力をどう固定長のブロック処理に落とし込むか（MD パディング）
- ブロック暗号から圧縮関数を作る3つの構成（Davies-Meyer 系）
- 「非標準の仮定を置く」ことがなぜ危険なのか

---

## tree hashing vs Merkle–Damgård

任意長の入力を固定長ブロックずつ処理する方法には、大きく2つの系統がある。

```
Merkle–Damgård: ブロックを先頭から順番に、前の出力を次の入力にして逐次処理する（逐次的）
tree hashing:    ブロックを木構造に組み、独立したサブツリーを並列に処理してから統合する
```

MD4 系譜（後述）はすべて Merkle–Damgård を採用した——**当時は並列計算よりも
実装の単純さと省メモリが優先された**ため。tree hashing は並列化に向くが
実装が複雑になる。BLAKE3 など近年の設計は tree hashing を採用する例もある。

---

## MD パディング：任意長を固定長ブロックに揃える

Merkle–Damgård はブロック単位でしか処理できないため、入力を必ず
ブロックサイズの倍数に揃える必要がある。

```
① メッセージの末尾に 1 ビットの "1" を付加する
② 続けて "0" を、次のブロック境界の少し手前まで埋める
③ 最後に、元のメッセージの「長さ」を固定長のフィールドとして書き込む
```

**なぜ長さを末尾に符号化するのか**——これは長さ拡張攻撃を防ぐためではなく
（それは別の弱点として残る、[`../04_hash-and-mac.md`](../04_hash-and-mac.md) 参照）、
**パディングの曖昧性を消すため**である。長さの情報がなければ、
末尾に0が並ぶ異なる長さの2つのメッセージが同じパディング後の
ブロック列になってしまう可能性がある——長さを刻むことで、
どんな2つの相異なるメッセージも異なるブロック列に写ることが保証される。

**最終ブロックだけ特別扱いする理由もここにある。** 長さ情報を含む
最後のブロックは、他の通常ブロックとは異なる意味を持つため、
実装上は別処理として扱われることが多い。

---

## ブロック暗号を圧縮関数に変える：Davies–Meyer 系

圧縮関数 `f(h, m)` を、ブロック暗号 `E` を使って構成する3つの標準的な方法がある
（`h`: 直前のチェイン値, `m`: 現在のメッセージブロック）。

```
Davies–Meyer:        f(h, m) := E_m(h) XOR h        （鍵をメッセージ、平文をチェイン値にする）
Matyas–Meyer–Oseas:   f(h, m) := E_h(m) XOR m        （鍵をチェイン値、平文をメッセージにする）
Miyaguchi–Preneel:    f(h, m) := E_h(m) XOR m XOR h  （MMO に h をもう一度混ぜる）
```

**共通する発想**——ブロック暗号は鍵さえ知っていれば可逆（=一方向性がない）だが、
出力に **入力そのものを XOR で混ぜ戻す**ことで、
可逆性を意図的に壊し一方向性を作り出している。これが Davies–Meyer 系全体に共通する仕掛けである。
SHA-1, SHA-2 は Davies–Meyer 構成を採用している。

---

## 落とし穴：非標準の仮定を置くこと

Davies–Meyer 系の安全性証明は、**内部で使うブロック暗号が理想的な
ランダム置換（ideal cipher）として振る舞う**という強い仮定の上に成り立つ。

これは実務上の制約を生む。**汎用のブロック暗号ライブラリをそのまま
圧縮関数の中身に流用してよいわけではない**——鍵スケジュールが
弱かったり、特定の鍵で構造的な弱点を持つ暗号は、たとえ暗号化用途としては
十分安全でも、ハッシュの圧縮関数として使うと安全性が崩れることがある。

### ブロック長と鍵スケジュールの制約

さらに、圧縮関数の設計はブロック暗号のパラメータに縛られる。

```
チェイン値の長さ = ブロック暗号のブロック長で決まる
メッセージブロックの長さ = 鍵スケジュールが受け付ける鍵長で決まる
```

出力長を伸ばしたいなら、ブロック長の大きい専用のブロック暗号を
新たに設計する必要が生じる——**既存のブロック暗号を流用する制約が、
そのままハッシュ関数の設計自由度を縛る**。

---

## MD4 の系譜

Ronald Rivest が1990年に設計した **MD4** が、この系統の起点である。
48ステップ（3ラウンド × 16ステップ）という構造は、後継の MD5・SHA-1にも
引き継がれた（MD5 は4ラウンド × 16 = 64ステップに拡張）。

```
MD4 (1990) → MD5 (1992, 廃止) → SHA-1 (1995, 廃止) → SHA-2 (2001, 現行)
```

各世代がどう破られたか（衝突攻撃の詳細）は
[`../04_hash-and-mac.md`](../04_hash-and-mac.md) が本体。
ここで押さえるべきは、**「ブロック暗号から圧縮関数を作る」という設計思想自体は
MD4 から SHA-2 まで一貫している**という系譜である。

## 演習（解答つき）

1. MD パディングで「メッセージの長さ」を末尾に符号化するのは何を防ぐためか。
2. Davies–Meyer 構成 `f(h,m) = E_m(h) XOR h` が、ブロック暗号の可逆性にもかかわらず
   一方向性を持つのはなぜか。
3. 既存の汎用ブロック暗号ライブラリを、そのままハッシュ関数の圧縮関数に転用することが
   危険な場合があるのはなぜか。

<details><summary>解答</summary>

1. 長さ情報がなければ、末尾に0が続く異なる長さの複数のメッセージが同じパディング後の
   ブロック列に写ってしまう可能性がある。長さを末尾に刻むことで、
   異なるメッセージは必ず異なるブロック列になることが保証され、パディングの曖昧性が消える。
2. ブロック暗号 `E_m` は鍵 `m` を知っていれば可逆だが、圧縮関数の出力には
   入力 `h` がそのまま XOR で混ぜ戻されている。これにより「出力から `h` を復元する」
   ことと「`E_m` を復号する」ことが直接結びつかなくなり、可逆な暗号を使いながら
   全体としては一方向性を持つ関数を構成できる。
3. Davies–Meyer 系の安全性証明は、内部のブロック暗号が理想的なランダム置換
   （ideal cipher）として振る舞うという強い仮定に依存する。汎用暗号は暗号化用途として
   十分安全でも、鍵スケジュールの弱さなど特定の構造的性質を持つことがあり、
   その性質がハッシュの圧縮関数としての安全性証明の前提を壊すことがある。

</details>
