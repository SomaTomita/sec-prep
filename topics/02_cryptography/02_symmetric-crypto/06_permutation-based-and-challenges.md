# 06. 置換ベース暗号と未解決問題

> 親: [README](./README.md) ｜ 前: [05 ブロック暗号からハッシュへ](./05_hashing-from-block-ciphers.md) ｜ 層: 基礎(Layer 1)

[05](./05_hashing-from-block-ciphers.md) はブロック暗号からハッシュを作った。
ここではその逆——**鍵を使わない置換だけ**を出発点にして、
ハッシュも暗号も認証も同じ部品から作るという第三の設計思想を見る。
最後に、対称鍵暗号の未解決問題と、それが新しい応用でどう問われ直されているかに触れる。

**この1ページで分かること**

- 置換ベース暗号という設計思想が Davies–Meyer 系と何が違うか
- Keccak の 3D 状態と duplex 構成の仕組み
- 軽量暗号・MPC/FHE 向け暗号という2つの新しい要求

---

## 置換ベース暗号という設計思想

Davies–Meyer 系（[05](./05_hashing-from-block-ciphers.md)）は
「ブロック暗号（鍵付きの可逆変換）」を土台にハッシュを作った。

置換ベース暗号はこれを逆転させる——**鍵を使わない固定の置換 `P`**（それ自体は
可逆だが、鍵に依存しない）を唯一の部品とし、**その使い方（モード）を変えるだけで**
ハッシュ・暗号化・MAC・AEAD のすべてを構成する。

```
Davies–Meyer系: ブロック暗号（鍵つき）が土台 → その上にハッシュを構成する
置換ベース:     鍵なし置換 P が土台          → 使い方だけでハッシュにも暗号にもなる
```

**利点は部品が1つで済むこと。** 暗号設計者は `P` の安全性だけを解析すればよく、
用途ごとに別の一次プリミティブを設計・検証する必要がなくなる。
SHA-3/Keccak がこの設計思想の代表例である。

---

## Keccak の 3D 状態

SHA-3 のスポンジ構成（[`../04_hash-and-mac.md`](../04_hash-and-mac.md) で「吸収・絞り出し」として既出）が
内部で使う置換 `Keccak-f` は、状態を**5×5×w ビットの3次元配列**として扱う
（`w` はレーン長。SHA-3 標準では `w=64`、状態全体は `5×5×64=1600bit`）。

```
状態 = 5×5 個の「レーン」(lane) の集合
      各レーンは w bit の縦方向のビット列
```

ラウンド関数は、この3次元構造に対する5つのステップ（θ, ρ, π, χ, ι）から成る——
行方向・列方向・レーン内といった**異なる軸に沿った混合**を組み合わせることで、
[02](./02_block-cipher-architecture.md) の拡散と混同を、SPN とは異なる幾何構造で実現している。

---

## duplex 構成：吸収と絞り出しを1つに

スポンジ構成の吸収フェーズと絞り出しフェーズを独立させず、
**1回の呼び出しで入力の注入と出力の取り出しを同時に行える**ように一般化したのが
duplex 構成である（Bertoni, Daemen, Peeters, Van Assche, 2011年）。

```
sponge:  吸収（全入力を先に処理）→ 絞り出し（その後に出力を生成）という2段階
duplex:  入力ブロックを渡すたびに、その場で出力ブロックも受け取れる（対話的）
```

**この対話性が AEAD との相性を生む**——duplex 構成1つで、
「関連データを吸収しつつ暗号文を絞り出す」という AEAD の要件
（[04](./04_modes-and-aead.md)）を、追加のブロック暗号もモードも使わずに実現できる。
置換1つが「ハッシュ・暗号化・認証」を兼ねるという設計思想の到達点がここにある。

---

## 未解決問題：基本部品の安全性証明はない

Davies–Meyer 系も置換ベースも、**土台となる基本部品（ブロック暗号 `E` や置換 `P`）
自体の安全性は証明されていない**——両者とも「この部品は十分ランダムに見える」という
経験的な信頼（暗号解読の蓄積によって裏付けられる）の上に成り立っている。

これは [03](./03_aes-internals.md) の AES の S-box 設計と同じ構図——
**証明ではなく、長年の攻撃者コミュニティによる解析に耐えたという実績**が、
現在使われている暗号の安全性の実質的な根拠になっている。

---

## 新しい要求①：軽量暗号

IoT・RFID タグなど、計算資源・電力が極端に制約された環境向けに、
AES より小さい回路面積・少ない消費電力で動く暗号が求められてきた。

NIST は軽量暗号の標準化プロジェクトを実施し、2023年に **Ascon** を選定、
2025年8月13日に **NIST SP 800-232** として発行した。Ascon も置換ベースの設計であり、
本ファイルで見た duplex 構成の考え方を軽量な置換に適用した AEAD である。

---

## 新しい要求②：MPC/FHE 向け暗号

秘密計算（MPC）・準同型暗号（FHE）の内部で対称鍵暗号を評価する場合、
**AES のような S-box 中心の設計は「乗算の回数」がボトルネックになる**——
MPC/FHE では XOR はほぼ無料だが、非線形演算（乗算・S-box）のコストが極めて高い。

これに対応するため、**乗法深度（multiplicative depth）を最小化する**ことを
目的にした専用の暗号設計（例: 低乗算複雑度を目指したストリーム暗号・ブロック暗号）が
近年研究されている。詳細は
[`../06_advanced-topics-map.md`](../06_advanced-topics-map.md) の MPC/FHE 領域を参照。

## 演習（解答つき）

1. 置換ベース暗号が Davies–Meyer 系と比べて「部品が1つで済む」と言えるのはなぜか。
2. duplex 構成が sponge 構成の単純な2段階（吸収→絞り出し）と違い、AEAD に向いているのはなぜか。
3. AES の S-box や Keccak の置換の安全性が「証明」ではなく何によって支えられているか。

<details><summary>解答</summary>

1. Davies–Meyer 系はブロック暗号（鍵つき）を土台にハッシュを構成するため、
   暗号化用途とハッシュ用途で別々に一次プリミティブの安全性解析が必要になりうる。
   置換ベースは鍵を使わない固定の置換1つだけを土台にし、使い方（モード）を変えるだけで
   ハッシュ・暗号化・MAC・AEAD のすべてを構成できるため、解析すべき一次プリミティブが1つで済む。
2. sponge は「全入力を吸収してから出力を絞り出す」という2段階の構成であり、
   入力と出力を交互にやり取りする用途には向かない。duplex は入力ブロックを渡すたびに
   その場で出力ブロックも受け取れる対話的な構成のため、関連データを吸収しながら
   暗号文を絞り出すという AEAD の要件を、追加のモードなしに1つの構成で満たせる。
3. 証明ではなく、長年にわたる暗号解読コミュニティによる集中的な解析に耐えてきたという
   経験的な実績によって支えられている。基本部品自体の安全性は数学的に証明されておらず、
   「十分ランダムに見える」という信頼が実質的な根拠になっている。

</details>
