# 02. ブロック暗号の設計思想

> 親: [README](./README.md) ｜ 前: [01 ストリーム暗号と LFSR](./01_stream-ciphers-and-lfsr.md) ｜ 次: [03 AES の内部構造](./03_aes-internals.md) ｜ 層: 基礎(Layer 1)

**この1ページで分かること**

- 換字暗号の弱点（頻度分析）が「コードブック」という発想を生んだ経緯
- Shannon の「拡散と混同」という2つの性質と、それを反復で実現する理由
- Feistel と SPN という2つの可逆構造の違い

ブロック暗号は「固定長の塊（ブロック）を、鍵で決まる方法で別の塊に置き換える巨大な対応表」。ストリーム暗号が乱数列を作るのに対し、こちらは**塊そのものを可逆に混ぜる**。

## 最小の例: 2 bit ブロックのコードブック

| 入力 | 鍵 k₁ での出力 | 鍵 k₂ での出力 |
|---|---|---|
| `00` | `10` | `01` |
| `01` | `11` | `00` |
| `10` | `00` | `11` |
| `11` | `01` | `10` |

鍵が変わると表が総入れ替えになり、どの表も**出力が重複しない**（可逆）。128 bit ブロックでは行が 2¹²⁸ 個になり表を持てないので、「鍵から表を**計算する**」のがブロック暗号。

---

## 換字暗号 → 頻度分析 → コードブック

```mermaid
flowchart LR
  A["換字暗号: 1 文字を置換"] -->|"頻度分析で破れる"| B["コードブック: 単語ごとに置換"]
  B -->|"表の配布・管理が非現実的"| C["ブロック暗号: 鍵から表を計算"]
  C --> D["理想は鍵ごとのランダム置換。計算で見分けられない = PRP"]
```

換字暗号は言語の統計的偏り（英語なら `e` が最頻）から置換表が復元される（頻度分析）。単位を単語・句に広げた**コードブック**は偏りが薄まるが、全入力の表を事前配布するのが非現実的。
ブロック暗号は「鍵から表を計算するアルゴリズム」に変え、事実上「鍵の数だけコードブックがある」状態を配布なしで実現する。「ランダムな置換と計算量的に見分けがつかない」が **PRP（擬似ランダム置換）** の定義（形式的定義は [Crypto I 講義ノート](../../courses/coursera-crypto1/04_block-ciphers/README.md)）。

---

## Shannon の交互適用：拡散と混同

Claude Shannon は、暗号が備えるべき性質を2つに整理した。

| 性質 | 意味 | 欠けると |
|---|---|---|
| 拡散 (diffusion) | 平文 1 bit の変化が暗号文の多くの bit に広がる | 局所的な偏りが残る |
| 混同 (confusion) | 鍵と暗号文の関係が単純な代数式で結べない | 鍵の影響が薄く非線形性が不足 |

Shannon は 2 つを**交互に繰り返す**ことを提案した。パン生地の「延ばして畳む」の反復と同じで、単純な操作の積み重ねが全体の均一な混合を生む。
`ラウンド関数（拡散+混同の 1 回分）を r 回繰り返す = 反復暗号`。1 ラウンドは単純でよく、**ラウンド数が安全性を生む**——AES を含む現代ブロック暗号の共通思想。

---

## 可逆性をどう保証するか：Feistel 構造

ラウンド関数は複雑でよいが、**復号できなければならない**（全体が全単射）。Feistel 構造は**中身の関数 F が可逆でなくてもよい**工夫でこれを解決する。

```
入力ブロックを左右 (L, R) に分割
各ラウンド:
    L' = R
    R' = L XOR F(R, ラウンド鍵)
```

**F が何であっても必ず可逆。** 復号は `L = R' XOR F(L', 鍵)`, `R = L'`——F を逆算する必要がない。F の中身と復号可能性を切り離せるのが強み。DES が採用。

---

## もう一つの選択肢：SPN 構造

SPN（Substitution-Permutation Network）は**各段階を可逆な演算だけで組む**。S-box（小ブロック単位の非線形な可逆換字表）と P-box / 線形変換（位置の並べ替え・線形混合）がどちらも可逆なので、**各層を逆順にたどれば復号できる**。Feistel の「半分だけ変換」の迂回が要らない。

### Feistel vs SPN

| | Feistel | SPN |
|---|---|---|
| ラウンド関数の可逆性 | **不要**（構造が可逆性を保証） | **各層が可逆である必要がある** |
| 1ラウンドあたりの拡散 | 半分のブロックにしか及ばない | ブロック全体に及びやすい |
| 代表例 | DES, Blowfish | AES, Serpent |
| 暗号化と復号の回路 | ほぼ共通化できる | 逆変換の実装が別途必要なことが多い |

優劣ではなくトレードオフ。Feistel は非線形関数の自由度が高く、SPN は少ないラウンドで全体拡散しやすい。AES が SPN を選んだ理由は [03](./03_aes-internals.md)。

---

## DES と 3DES：この系譜の実例（要点のみ）

- **DES**（1977年, FIPS 46）: Feistel 構造・56bit 鍵・16ラウンド。
  鍵長が短く総当たりに敗れた。
- **3DES**: DES を3回鎖状に適用し実効鍵長を伸ばした延命策。処理が遅く、
  64bit ブロック長に起因する Sweet32 攻撃の対象にもなった。

破られ方の詳細は [Crypto I 講義ノート](../../courses/coursera-crypto1/04_block-ciphers/README.md)が本体。要点は 1 つ——**Feistel の欠陥ではなく、鍵長・ブロック長というパラメータが時代遅れになった**。構造とパラメータは別問題で、AES は SPN と可変鍵長（128/192/256 bit）を選んだ。

## 演習（解答つき）

1. 「コードブックをアルゴリズムで代替する」という発想が解決した問題は何か。
2. Feistel 構造で、ラウンド関数 F 自体が可逆である必要がないのはなぜか。
3. SPN 構造が Feistel 構造と比べて「各層が可逆でなければならない」制約を持つ理由を述べよ。

<details><summary>解答</summary>

1. 本物のコードブックは、あらゆる入力に対応する対応表を事前に用意し、
   安全に配布・保管する必要があり非現実的だった。鍵からアルゴリズムで表を
   計算することで、表そのものを保存・配布する必要をなくし、
   かつ鍵ごとに異なる「事実上のコードブック」を持てるようにした。
2. Feistel 構造は `L' = R, R' = L XOR F(R, k)` という形を取り、復号時には
   `R' XOR F(L', k)` によって `L` を、`L'` によって `R` を復元できる。
   この復元の手順は F 自体を逆に計算することを一切要求しない——
   F は一方向にしか計算されず、構造の対称性だけで可逆性が保証されるため。
3. SPN には Feistel のような「半分を素通りさせて残り半分とだけ混ぜる」迂回がなく、
   S-box や線形変換がブロック全体に直接作用する。復号するには、暗号化で使った
   各変換（S-box、線形変換）をそれぞれ逆向きに計算する必要があるため、
   個々の構成要素自体が可逆でなければならない。

</details>
