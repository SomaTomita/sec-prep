# 05. 安全性の定義と KEM

> 前: [04 デジタル署名](./04_digital-signatures.md) ｜ 層: 基礎(Layer 1)
> 親: [README](./README.md)

`01`〜`04` では個別の方式（RSA・DH・ECC・署名）を見た。ここでは**「安全である」とは
何を意味するのか**を定義する枠組みと、公開鍵暗号が実務でどう使われるか——
教科書の説明とは違う **KEM** という形——を扱う。

**この1ページで分かること**

- 安全性が「ゲーム」と「優位性」で定義される理由
- IND-CPA から IND-CCA2 までの階層と、なぜ CCA2 が目標になるのか
- 実務では公開鍵で**メッセージを暗号化しない**（KEM/DEM）こと

---

## 3つのアルゴリズムという定式化

公開鍵暗号方式は、3つのアルゴリズムの組として定義される。

```
KeyGen(λ) → (pk, sk)   λ はセキュリティパラメータ（例: 128ビット安全を要求）
Enc(pk, m) → c         公開鍵で暗号化
Dec(sk, c) → m         秘密鍵で復号
```

`λ` を入力に取る点が重要。「この方式は安全か」ではなく
**「何ビットの安全性を要求するとき、鍵長をどう選ぶか」**という問いの形にしている。
鍵長と安全性の対応は
[`../../01_prerequisites/01_math-for-crypto/05_info-theory/04_key-length-security.md`](../../01_prerequisites/01_math-for-crypto/05_info-theory/04_key-length-security.md) を参照。

---

## 安全性はゲームで定義する

「安全」を定義するには、**攻撃者に何ができて、何を達成したら破れたことになるか**を
厳密に書く必要がある。標準的な方法は次のゲームである。

```
1. 挑戦者が鍵を生成し、公開鍵 pk を攻撃者に渡す
2. 攻撃者が2つの平文 m0, m1 を選んで提出する（同じ長さ）
3. 挑戦者が b ∈ {0,1} をランダムに選び、c = Enc(pk, m_b) を返す
4. 攻撃者が b を当てようとする
```

ここで測るのは**正答率そのものではない**。攻撃者は何もしなくてもコインを投げれば
1/2 の確率で当たるので、意味があるのは **1/2 からのずれ**である。

```
優位性 (advantage) = |Pr[攻撃者が当てる] − 1/2|
```

**この優位性が無視できるほど小さい**ことが安全性の定義になる。
「絶対に破れない」ではなく「破る優位性が実質ゼロ」という形をとる点が、
現代暗号の定義の作りである。

> 同じ形の定義を対称鍵暗号でも使う（意味論的安全性）。
> ゲームによる定義の考え方そのものは、`courses/coursera-crypto1/03_stream-ciphers/` の
> 意味論的安全性の議論と共通である。

## IND-CPA から IND-CCA2 へ

攻撃者に**何を許すか**を変えると、強さの異なる安全性の階層ができる。
分類と相互関係は Bellare–Desai–Pointcheval–Rogaway (CRYPTO'98) が整理した。

| モデル | 攻撃者に許すもの | 名前の由来 |
|---|---|---|
| **IND-CPA** | 公開鍵があるので**自分で好きな平文を暗号化できる** | Chosen-Plaintext Attack |
| **IND-CCA1** | 加えて、挑戦暗号文を受け取る**前**なら復号オラクルを使える | 非適応的 CCA |
| **IND-CCA2** | 挑戦暗号文を受け取った**後**も復号オラクルを使える（ただし挑戦暗号文自身は問い合わせ禁止） | 適応的 CCA |

**IND-CPA は公開鍵暗号では自動的に要求される。** 公開鍵は誰でも持っているので、
攻撃者が自分で暗号化できるのは前提条件であり、選択肢ではない。
だから**決定論的な暗号化は公開鍵では即座に破れる**——同じ平文が同じ暗号文になるなら、
`m0` を自分で暗号化して比べるだけで `b` が分かる。教科書 RSA にパディングが必要な理由がこれ
（[`01_rsa/04_padding-and-attacks.md`](./01_rsa/04_padding-and-attacks.md)）。

### なぜ CCA2 が目標なのか

「復号オラクルが使える」という仮定は不自然に強く見える。しかし**現実のシステムは
意図せず復号オラクルを提供してしまう**。

| 実際に起きたこと | どう復号オラクルになったか |
|---|---|
| RSA の Bleichenbacher 攻撃 | サーバがパディングの妥当性で異なる応答を返した |
| CBC のパディングオラクル攻撃（POODLE 等） | 同様に、復号後のパディング検証の成否が観測できた |

**エラーメッセージの違い・応答時間の差が、そのまま復号オラクルになる。**
攻撃者は暗号文を少しずつ改変して問い合わせるだけで、鍵を知らずに復号を進められる。

つまり CCA2 は「理論的に厳しすぎる想定」ではなく、**実装が現実に晒される状況**である。
これが「CCA2 安全でなければ実用に耐えない」と言われる理由。
既存の攻撃事例は
[`01_rsa/04_padding-and-attacks.md`](./01_rsa/04_padding-and-attacks.md) と
[`../02_symmetric-crypto/README.md`](../02_symmetric-crypto/README.md) を参照。

## KEM：公開鍵でメッセージを暗号化しない

教科書は「公開鍵でメッセージを暗号化する」と説明するが、**実務ではそうしない**。
公開鍵演算は重く、扱えるデータ長も法のサイズに制限される。

実際に使われるのは **KEM/DEM** という構成である。

```
KEM (Key Encapsulation Mechanism):
    Encap(pk) → (c, k)      ランダムな鍵 k を作り、その「封筒」c を公開鍵で作る
    Decap(sk, c) → k        秘密鍵で封筒を開いて k を取り出す

DEM (Data Encapsulation Mechanism):
    k を対称鍵として、本体のデータを AEAD で暗号化する
```

**要点は「メッセージを選んで暗号化する」のではなく「鍵を運ぶ」こと。**
送りたい内容を公開鍵演算に通す必要がなくなるため、パディングにまつわる
微妙な問題も避けやすくなる。

これは [`../02_symmetric-crypto/README.md`](../02_symmetric-crypto/README.md) の
**ハイブリッド暗号**を、公開鍵側の視点から見たものである（同じ仕組みの別の断面なので、
利用側の説明はそちらを参照）。

> **耐量子暗号が「KEM」と名乗る理由**もここにある。ML-KEM（FIPS 203）は
> 「メッセージを暗号化する方式」ではなく**鍵を運ぶ方式**として標準化された——
> 実務で必要なのがそれだからである
> （[`../06_advanced-topics-map.md`](../06_advanced-topics-map.md)）。

## 署名側の対応する定義：EUF-CMA

署名にも同じ形の定義がある。

```
EUF-CMA (Existential Unforgeability under Chosen-Message Attack):
  攻撃者は好きなメッセージの署名を要求できる（署名オラクル）
  その上で、一度も署名を求めていないメッセージについて
  有効な署名を1つでも作れたら「破れた」とみなす
```

**「意味のあるメッセージを偽造できたら」ではなく「何か1つでも偽造できたら」**
という厳しい基準になっている点に注意。攻撃者にとって都合のよいメッセージが
何であるかを事前に決めつけないためである。
具体的な署名方式は [`04_digital-signatures.md`](./04_digital-signatures.md) が本体。

## 演習（解答つき）

1. 安全性を「攻撃者の正答率」ではなく「1/2 からのずれ（優位性）」で測るのはなぜか。
2. パディングを施さない教科書 RSA が IND-CPA すら満たさない理由を、
   上記のゲームの手順に沿って説明せよ。
3. KEM を使うと、公開鍵で直接メッセージを暗号化する場合と比べて何が改善するか。2つ挙げよ。

<details><summary>解答</summary>

1. 攻撃者は何もせずコインを投げるだけで 1/2 の確率で正解できるため、正答率そのものは
   安全性の指標にならない。意味があるのは「当て推量より**どれだけ**うまくやれるか」であり、
   それが 1/2 からのずれ＝優位性である。優位性が無視できるほど小さければ、
   攻撃者は本質的に何も学べていないことになる。
2. 教科書 RSA は決定論的で、同じ平文が常に同じ暗号文になる。ゲームの手順2で攻撃者が
   `m0, m1` を提出し、手順3で `c = Enc(pk, m_b)` を受け取ったとき、攻撃者は
   **公開鍵を持っているので自分で `Enc(pk, m0)` を計算できる**。それが `c` と一致すれば
   `b=0`、しなければ `b=1` と確実に判定できる。優位性が 1/2（つまり常に正解）になるため
   IND-CPA を満たさない。
3. ①**公開鍵演算の対象が短い鍵だけになる**ので、長いデータでも高速に扱える
   （公開鍵演算は対称鍵より桁違いに重い）。②**メッセージを公開鍵演算に通さない**ため、
   平文の構造に起因するパディング関連の攻撃面を減らせる。
   他に「扱えるデータ長が法のサイズに制限されなくなる」も可。

</details>
