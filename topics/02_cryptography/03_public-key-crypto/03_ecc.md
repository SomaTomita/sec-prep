# 03. 楕円曲線暗号（ECC）

> 前: [02 Diffie–Hellman](./02_dh.md) ｜ 次: [04 デジタル署名](./04_digital-signatures.md) ｜ 層: 基礎(Layer 1)
> 親: [README](./README.md)

**この1ページで分かること**

- 楕円曲線上の点の「加算」がどう定義され、それが暗号に使える群になる仕組み
- ECDH ＝ DH の `g^a` を `aG` に置き換えるだけ、という載せ替えの実際（玩具曲線で計算）
- 同じ安全性に必要な鍵長の RSA/DH との比較と、実用曲線（P-256 / Curve25519）の信頼性の論点

[02](./02_dh.md) の最後で触れた通り、DH は `Z_p^*` に限らず**離散対数問題が定義できる巡回群**なら
何でも使える。楕円曲線上の点がなす群を使うと、**同じ安全性をずっと短い鍵長**で達成できる
（安全性の根拠は [`../../01_prerequisites/01_math-for-crypto/03_number-theory/05_hard-problems.md`](../../01_prerequisites/01_math-for-crypto/03_number-theory/05_hard-problems.md)
で扱った ECDLP。本ファイルでは重複させず、「群がどう作られているか」に絞る）。
1985年、Neal Koblitz と Victor Miller が独立に発表（H.W. Lenstra の素因数分解研究が着想源）。

---

## 楕円曲線と群の定義

```
楕円曲線（短ワイエルシュトラス形、有限体 GF(p) 上, p>3）:
  E: y² = x³ + ax + b   （4a³+27b² ≠ 0 で特異点なし）

群の要素: 曲線上の点 (x,y) の全体 + 「無限遠点 O」（単位元）
群演算「+」: 2点を「足す」と別の1点になる（下記で定義）
```

`O` が単位元（`P + O = P`）で、各点 `P=(x,y)` の逆元は `-P=(x,-y mod p)`
（`P + (-P) = O`）。この「+」が結合律・可換律を満たす**アーベル群**になることが
楕円曲線暗号の土台（証明は割愛、Silverman *The Arithmetic of Elliptic Curves* 等参照）。

### 点の加算・倍加の公式

```
P=(x1,y1), Q=(x2,y2) として R=P+Q=(x3,y3) を求める:

P≠Q のとき（加算）:  λ = (y2-y1)/(x2-x1) mod p
P=Q のとき（倍加）:  λ = (3x1²+a)/(2y1) mod p

x3 = λ² - x1 - x2  (mod p)
y3 = λ(x1-x3) - y1 (mod p)
```

幾何学的には「2点を通る直線が曲線と交わる3点目を x 軸で折り返す」操作
（倍加は接線を使う）に対応するが、実装・計算上は上の代数公式だけ使えば十分。

---

## 小さな数値例：`y² = x³ + 2x + 2 (mod 17)`

`a=2, b=2, p=17` として計算する（全て手計算・プログラムで検算済み）。

```
この曲線上の点は（Oを除いて）18個、G=(5,1) を選ぶと G の位数はちょうど19（素数）
→ G は単位元Oを含む19個の点全体（巡回群）を生成する
```

`G=(5,1)` が曲線上にあることを確認: `1² = 1`、`5³+2·5+2 = 137 ≡ 1 (mod 17)` ✓

### 倍加: `2G` を求める

```
λ = (3·5²+2)/(2·1) mod 17 = 77 · inv(2,17) mod 17 = 9 · 9 = 81 ≡ 13 (mod 17)
x3 = 13² - 5 - 5 = 159 ≡ 6 (mod 17)
y3 = 13·(5-6) - 1 = -14 ≡ 3 (mod 17)
∴ 2G = (6, 3)
```

### 加算: `G + 2G` が `3G` に一致するか確認

```
λ = (3-1)/(6-5) mod 17 = 2
x3 = 2² - 5 - 6 = -7 ≡ 10 (mod 17)
y3 = 2·(5-10) - 1 = -11 ≡ 6 (mod 17)
∴ G + 2G = (10, 6) = 3G   ✓（直接計算した 3G と一致）
```

同様に `4G=(3,1)`, `5G=(9,16)` と続く。RSA のべき乗（[`01_rsa/02`](./01_rsa/02_encryption-decryption.md)
の2乗繰り返し法）と全く同じ発想の **ダブル・アンド・アド法（double-and-add）** で
`nG` を `O(log n)` 回の加算で計算できる。

---

## ECDH：DH をそのまま楕円曲線に載せ替える

DH の `g^a mod p` を `aG`（`G` を `a` 回加算した点）に置き換えるだけ。

```
公開パラメータ: 曲線 E、位数が大きい素数の生成点 G
Alice: 秘密 a → 公開 A = aG
Bob:   秘密 b → 公開 B = bG
共有鍵: Alice は a·B = a(bG) = (ab)G、Bob は b·A = b(aG) = (ab)G  ← 一致
```

上の玩具曲線（`n=19`）で `a=6, b=11` を選ぶと:

```
A = 6G = (16,13),   B = 11G = (13,10)
Alice: a·B = 6·(13,10) = (7,6)
Bob:   b·A = 11·(16,13) = (7,6)   ← 一致 ✓
```

盗聴者は `G, A, B` を見ても `a, b`（したがって共有鍵）を求めるには
**ECDLP**（`Q=nG` から `n` を求める問題）を解く必要がある。

---

## なぜ鍵長が短くて済むか

一般の有限体上の DLP や素因数分解には準指数時間の攻撃（指数計算法・GNFS）が知られるが、
一般の楕円曲線群には準指数時間アルゴリズムが知られておらず、最良でも
Pollard の ρ法（群の位数の平方根程度の指数時間）しかない
（詳細比較は [`03_number-theory/05_hard-problems.md`](../../01_prerequisites/01_math-for-crypto/03_number-theory/05_hard-problems.md)）。
結果として **256bit の楕円曲線 ≈ 3072bit の RSA/DH** という短さで同等の安全性になる。

| 安全性レベル（対称鍵換算） | ECC 鍵長 | RSA/DH 鍵長 |
|---|---|---|
| 128 bit | 256 bit | 3072 bit |
| 192 bit | 384 bit | 7680 bit |
| 256 bit | 512 bit（実用曲線は P-521 の 521 bit） | 15360 bit |

（NIST SP 800-57 の等価安全性の対応表より。）

---

## 実用の曲線：NIST P-256 と Curve25519

- **NIST P-256（secp256r1）**: 短ワイエルシュトラス形、係数はNISTが公表した「ランダムな」値。
  過去に **Dual_EC_DRBG**（NIST SP 800-90A で標準化された乱数生成器。同じく楕円曲線を使う）
  において、公表された定点 `P1, P2` の関係を NSA だけが知っている疑いが 2013年の
  Snowden のリーク文書で裏付けられ、出力から内部状態を復元できる**バックドア**の存在が
  指摘された（2014年に標準から撤回）。以来、曲線・定数のパラメータが
  「**nothing up my sleeve numbers**（作為のない値）」として検証可能かどうかが
  楕円曲線暗号の信頼性で重視されるようになった。
- **Curve25519 / X25519**（D. J. Bernstein、モンゴメリ形、RFC 7748, 2016年）:
  パラメータの生成過程が完全に公開・再現可能で、実装ミスが起きにくいよう設計
  （定数時間演算がしやすい、無効曲線攻撃 invalid-curve attack や小部分群攻撃への耐性）。
  TLS 1.3・Signal・SSH で広く採用。署名版 Ed25519 は [04](./04_digital-signatures.md) で扱う。

**実装上の注意（正しさ≠安全）**: RSA の教科書実装が危険だった（[`01_rsa/04`](./01_rsa/04_padding-and-attacks.md)）のと同様、
ECC も受け取った点が本当に曲線上・正しい部分群上にあるかを検証しないと
**無効曲線攻撃**（偽の点を送りつけて秘密鍵の情報を漏らす）が成立しうる。
数学的に正しい群演算だけでは実運用の安全性は保証されない。

## 演習（解答つき）

1. 上の玩具曲線（`p=17, a=2, b=2, G=(5,1)`）で `4G` を「`2G+2G`」として計算し、
   本文に挙げた `4G=(3,1)` と一致することを確認せよ（`2G=(6,3)` を使う）。
2. Curve25519 が NIST P-256 より「信頼性の観点で」優れているとされる理由を一言で述べよ。
3. なぜ 256bit の楕円曲線鍵が 3072bit の RSA 鍵と同程度の安全性を持つと言えるのか。

<details><summary>解答</summary>

1. `2G=(6,3)` なので `P=Q=(6,3)` の倍加公式を使う。
   `λ = (3·6²+2)/(2·3) mod17 = 110·inv(6,17) mod17`。`110 mod17=8`、`inv(6,17)=3`（`6·3=18≡1`）
   なので `λ=8·3=24≡7 (mod17)`。`x3=7²-6-6=37≡3(mod17)`。`y3=7·(6-3)-3=18≡1(mod17)`。
   `∴ 2G+2G=(3,1)=4G` ✓ 本文の値と一致。
2. Curve25519 のパラメータ生成過程は完全に公開・再現可能で「作為の余地」がない。
   NIST P-256 の定数は生成過程が不透明で、Dual_EC_DRBG のような疑念が過去に生じたため、
   透明性の面で Curve25519 が信頼されやすい。
3. 一般の楕円曲線群には準指数時間の攻撃アルゴリズムが知られておらず、最良の攻撃
   （Pollard の ρ法）でも群の位数の平方根程度の計算量が必要。素因数分解・有限体DLPは
   準指数時間で解けるため、同じビット数あたりの安全性がずっと低く、同等の安全性を得るには
   RSA/DHははるかに長い鍵長が必要になる。

</details>
