# 02. Diffie–Hellman 鍵共有

> 前: [01 RSA](./01_rsa/README.md) ｜ 次: [03 楕円曲線暗号](./03_ecc.md) ｜ 層: 基礎(Layer 1)
> 親: [README](./README.md)

**この1ページで分かること**

- 盗聴されている通信路の上で共有鍵を作る DH の仕組みと、指数法則だけで鍵が一致する理由
- DH 単体では中間者攻撃（＝攻撃者が両者の間に割り込み、双方と別々の鍵を作る攻撃）を防げないこと
- DHE が持つ前方秘匿性と、TLS 1.3 が RSA 鍵輸送を廃止した理由

1976年 Whitfield Diffie と Martin Hellman が発表。**世界初の公開鍵暗号アイデア**。
RSA が「暗号化・復号」の方式なのに対し、DH は目的が違う——
**盗聴されている通信路の上で、2者が共通の秘密（共有鍵）を作る**ための鍵共有プロトコル。
安全性の根拠は素因数分解ではなく **離散対数問題（DLP）**
（[`../../01_prerequisites/01_math-for-crypto/03_number-theory/05_hard-problems.md`](../../01_prerequisites/01_math-for-crypto/03_number-theory/05_hard-problems.md)）。

---

## プロトコル

```
公開パラメータ（事前に合意・公開）: 素数 p、生成元 g（＝べき乗 g, g², g³, … が群全体を巡る Z_p^* の元）

Alice                                    Bob
──────────────────────────────────────────────────
秘密 a を選ぶ（乱数）
A = g^a mod p  ─────────  A  ─────────→
                ←────────  B  ─────────  B = g^b mod p ← 秘密 b を選ぶ（乱数）

K = B^a mod p                            K = A^b mod p
  = (g^b)^a mod p                          = (g^a)^b mod p
  = g^(ab) mod p                           = g^(ab) mod p    ← 同じ値になる！
```

`a, b` は本人だけが知る秘密。ネットワーク上を流れるのは `p, g, A, B` だけで、
盗聴者はこれらを見ても `a` や `b`（したがって `K`）を計算できない、というのが安全性の主張。

---

## なぜ同じ値になるか

指数法則がそのまま mod p でも成り立つだけ:

```
(g^b)^a = g^(b·a) = g^(a·b) = (g^a)^b   (mod p)
```

掛け算の順序を入れ替えられる（可換）という、ただそれだけの事実で
「別々に計算したのに一致する」という魔法のような結果が生まれる。

---

## 小さな数値例（p=23, g=5 — 教科書で頻出の例）

```
公開: p=23, g=5
Alice: a=6 を選ぶ → A = 5^6 mod 23 = 8
Bob:   b=15 を選ぶ → B = 5^15 mod 23 = 19
```

**Alice の計算**: `K = B^a mod p = 19^6 mod 23`
```
19 ≡ -4 (mod 23) なので 19^2 ≡ 16,  19^3 ≡ 19·16 = 304 ≡ 5 (mod 23)
19^6 = (19^3)^2 ≡ 5^2 = 25 ≡ 2 (mod 23)
```

**Bob の計算**: `K = A^b mod p = 8^15 mod 23`（2乗繰り返し法で計算すると）`≡ 2 (mod 23)`

**両者とも K = 2 に一致** ✓。盗聴者は `p=23, g=5, A=8, B=19` を見ているが、
ここから `a=6` や `b=15`（や `K=2`）を求めるには離散対数を解く必要がある
（この例は数が小さいので総当たりで解けてしまうが、実用では `p` が2048bit以上）。

---

## 安全性の根拠：CDH と DDH

素因数分解ではなく、次の2つの仮定に安全性が依存する（どちらも DLP の困難性が前提）。

```
計算量的 Diffie–Hellman 仮定 (CDH):
  (g, g^a, g^b) から g^(ab) を計算するのは計算量的に困難

決定的 Diffie–Hellman 仮定 (DDH):
  (g, g^a, g^b, g^(ab)) と (g, g^a, g^b, g^z)（z はランダム）を区別するのも困難
```

DDH は CDH より**強い**仮定（DDH が破れれば CDH も破れるが、逆は必ずしも成り立たない）。
DH の鍵共有そのものは CDH の困難性で守られており、ElGamal 暗号など一部の方式は
より強い DDH の困難性を安全性証明の根拠にする。

---

## 弱点：認証がない（中間者攻撃）

DH プロトコルは**盗聴者**（受動的攻撃者）には強いが、**改ざんできる攻撃者**
（能動的攻撃者）には無力——`A` や `B` が本当に相手が送ったものかを確認する手段が
プロトコル自体に無い。

```
Alice ──A──→ [Mallory が横取り] ──A'──→ Bob
Alice ←──B'── [Mallory]         ←──B── Bob
```

Mallory は Alice とは `K1`、Bob とは `K2` という**別々の共有鍵**を確立し、
両者の通信をすべて中継しながら盗聴・改ざんできてしまう。DH 単体では
[`01_goals-and-primitives.md`](../01_goals-and-primitives.md) で見た「機密性」は狙えても
「認証」は一切提供しない。

**対策**: `A, B` にデジタル署名を付け、通信相手の公開鍵証明書で検証する
（TLS の `DHE-RSA` / `ECDHE-RSA` は、DH の値をサーバの RSA/ECDSA 秘密鍵で署名することで
この弱点を補っている）。

---

## 前方秘匿性（Forward Secrecy）と RSA 鍵輸送との対比

DH には RSA による鍵共有（[`01_rsa/02_encryption-decryption.md`](./01_rsa/02_encryption-decryption.md)
の「RSA による鍵共有のイメージ」）にはない利点がある。

| 方式 | 仕組み | 長期鍵が将来漏れたら |
|---|---|---|
| RSA 鍵輸送 | 共通鍵 K を Bob の公開鍵で暗号化して送る | 過去に記録された全通信が遡って復号される |
| DHE（使い捨てDH） | セッションごとに一時的な `a, b` で DH を実行し廃棄 | 過去のセッション鍵は再現できない ＝ **前方秘匿性（forward secrecy）** |

この利点のため TLS 1.3 では RSA 鍵輸送が廃止され、**DHE / ECDHE のみ**が
鍵共有方式として残っている。

---

## 実装上の注意：Logjam 攻撃（2015年）

CVE-2015-4000。多くのサーバが**共通の小さい・使い回しの `p`**（512bit の輸出グレード
パラメータ等）を使っていたことを突いた攻撃。

- 攻撃者は特定の `p` に対して数千CPUコア×1週間規模の**事前計算**を1回行っておけば、
  以降はその `p` を使うどの接続に対しても**数分で個別の離散対数**を解ける。
- 中間者が TLS のネゴシエーションを操作し、脆弱な輸出グレード暗号スイート
  （`DHE_EXPORT`）に強制ダウングレードさせることで実際に悪用可能だった。

**教訓**: DH のパラメータ `p` は十分大きく（2048bit以上）、かつ使い回さない
（または広く検証された標準パラメータを使う）ことが必須。

---

## 群の一般化：楕円曲線への拡張

DH は `Z_p^*`（mod p の乗法群）に限定されない。**離散対数問題が定義できる巡回群なら
何でも使える**という一般性が DH の強み。楕円曲線上の点がなす群を使うのが ECDH で、
同じ安全性をずっと短い鍵長で達成できる（ECDLP の困難性は DLP よりも強い、
[`../../01_prerequisites/01_math-for-crypto/03_number-theory/05_hard-problems.md`](../../01_prerequisites/01_math-for-crypto/03_number-theory/05_hard-problems.md) 参照）。
→ [03 楕円曲線暗号](./03_ecc.md)

## 演習（解答つき）

1. `p=23, g=5` で Alice が `a=3`、Bob が `b=7` を選んだとき、`A, B` と共有鍵 `K` を求めよ。
2. なぜ DH は「暗号化方式」ではなく「鍵共有プロトコル」と呼ばれるのか、RSA と対比して一言で述べよ。
3. DHE（毎回使い捨ての鍵）と静的DH（固定の `a, b` を使い回す）で、前方秘匿性がある方はどちらか。

<details><summary>解答</summary>

1. `A = 5^3 mod 23 = 125 mod 23 = 10`。`B = 5^7 mod 23`：`5^7=5^6·5=8·5=40≡17 (mod23)` →
   `B=17`。共有鍵 `K = B^a mod p = 17^3 mod 23`：`17≡-6`, `17^2≡36≡13`,
   `17^3≡17·13=221≡221-207=14 (mod23)` → **K=14**。
   検算: `K=A^b mod p = 10^7 mod23`。`10^2=100≡8`, `10^4=8^2=64≡18`,
   `10^7=10^4·10^2·10=18·8·10=1440`。`1440 mod23`: `23·62=1426`, `1440-1426=14` → 一致 ✓。
2. RSA は「メッセージそのものを暗号化・復号する」方式。DH はメッセージを一切運ばず、
   両者が独立に同じ値を**計算して合意する**だけの手続きであり、暗号化操作を含まない。
3. **DHE**（毎回使い捨て）。静的DHでは秘密鍵 `a, b` が固定されているため、
   いずれか一方が漏洩すればそれ以降・それ以前を問わず全セッションの鍵 `K` が再計算できてしまう。

</details>
