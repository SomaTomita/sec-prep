# 04. FSM として見るストリーム暗号

> 親: [README](./README.md) ｜ 前: [03 PRG とキーストリーム](./03_prg-and-keystream.md) ｜ 層: 深掘り(Layer 2)

**この1ページで分かること**

- ストリーム暗号は「状態を更新しながら `Z` を吐く機械」= FSM（有限状態機械）として 1 枚の図で描ける
- `K` は秘密で 1 回だけ配送、`IV` は公開してよく毎回変える。この分担で同じ鍵を安全に使い回せる
- `P` と `C` が揃うと `Z` が漏れて改ざんも自由になる。だから MAC/AEAD が必要

## 動機

ストリーム暗号は「歯車を 1 つ回すごとに乱数を 1 bit 吐く機械」。それを **FSM（Finite State Machine, 有限状態機械）**の図に描き直す。最小の例を 3 歩:

| 歩 | 状態 | 出力 `Z` | 平文 `P` | 暗号文 `C = P ⊕ Z` |
|---|---|---|---|---|
| 0 | `101` | 1 | 1 | 0 |
| 1 | `010` | 0 | 0 | 0 |
| 2 | `001` | 1 | 1 | 0 |

受信側は同じ `K`・`IV` から同じ状態列を再現し、`C ⊕ Z` で `P` を得る。読むべき式は 2 本だけ。

```
暗号化:  C = P ⊕ Z
復号:    P = C ⊕ Z
```

左半分が暗号化、右半分が復号。**同じ機械**に `P` を入れるか `C` を入れるかの違いだけ。

## 図の読み方

```
        K ──┐          ┌── IV
            ▼          ▼
      ┌──────────────────────┐
      │  next state function  │◀─┐   状態を1つ先へ進める
      └──────────┬───────────┘  │
                 │ state ────────┘   （更新した状態が次の入力に戻る）
                 ▼
      ┌──────────────────────┐
      │    output function    │      状態から Z を取り出す
      └──────────┬───────────┘
                 ▼  Z（キーストリーム）
   P ───────────⊕──────────▶ C
```

### 記号の対応

| 記号 | 意味 | 前ページとの対応 |
|---|---|---|
| `K` | Key（秘密鍵） | PRG のシード |
| `IV` | Initialization Vector（初期化ベクトル） | 同じ `K` でも毎回違う `Z` を出すための値 |
| `P` | Plaintext（平文） | — |
| `C` | Ciphertext（暗号文） | — |
| `Z` | Keystream（キーストリーム） | PRG の出力 |
| `⊕` | XOR | [01](./01_vernam-and-otp.md) と同じ |
| next state function | 現在の状態から次の状態を作る | LFSR のシフト＋フィードバック |
| output function | 現在の状態から `Z` を取り出す | LFSR の「右端ビットを出す」部分 |

### 状態が進むということ

FSM の肝は、内部に**状態（state）**を持ち、それを更新し続ける点にある。

```
state₀ ──next──▶ state₁ ──next──▶ state₂ ──next──▶ state₃ ──▶ …
   │                │                │                │
 output           output           output           output
   ▼                ▼                ▼                ▼
  Z₀               Z₁               Z₂               Z₃
```

`state₀` の決め方に `K` と `IV` の両方が効く。だから

- **`K` が同じで `IV` が違う** → 別のキーストリームが出る（＝同じ鍵を安全に使い回せる）
- **`K` も `IV` も同じ** → まったく同じキーストリームが出る（＝復号できる／使い回すと破綻する）

の2つが同時に成り立つ。

## 動かして確かめる

左が暗号化、右が復号。**両レーンは同じ `K` と `IV` を持つので、同じ `Z` を生成する**。
「1ステップ」で状態が1回更新され、`Z` が1ビット出て、XOR が実行される。

### 試してほしい操作

- **「IV を変える」** → `K` はそのままなのに状態列も `Z` も `C` も総入れ替えになる。
  これが IV の役目。
- 左レーンの `Z` と右レーンの `Z` が**毎ステップ一致している**ことを確認する。
  復号が成立する理由はこれ以上でも以下でもない。
- 平文 `P` を全部 `0` にしてみる → `C` がそのままキーストリーム `Z` になる。
  「暗号文と平文の両方を知られると `Z` が漏れる」＝**既知平文攻撃**の下地。

## なぜ元に戻るのか

同じ `Z` さえ再現できれば、あとは XOR の性質だけで戻る。

```
C     = P ⊕ Z
C ⊕ Z = (P ⊕ Z) ⊕ Z
      = P ⊕ (Z ⊕ Z)     （結合律）
      = P ⊕ 0           （Z ⊕ Z = 0）
      = P
```

暗号化装置と復号装置が同一でよいのはこのため。実装でも「暗号化関数」と「復号関数」は同じ 1 つの関数であることが多い。

## 試験用の最小形

覚えるのは結局これだけ。

```
        K + IV                    K + IV
           ↓                         ↓
      State / FSM               State / FSM
           ↓                         ↓
     Keystream Z               Keystream Z
           ↓                         ↓
 P ─────  XOR  ────▶ C     C ─────  XOR  ────▶ P
```

## 演習

1. `K` を固定したまま `IV` を毎回変える運用と、`IV` を固定して `K` を毎回変える運用がある。
   実際に採用されるのはどちらで、それはなぜか。
2. 攻撃者が `P` と `C` の両方を手に入れた。攻撃者は何を計算できるか。
   その値を使って何ができるか。
3. 同じ `K` と同じ `IV` で2つのメッセージ `P₁`, `P₂` を暗号化してしまった。
   何が起きるか。[01](./01_vernam-and-otp.md) のどの失敗と同型か。

<details><summary>解答</summary>

1. **`K` を固定し `IV` を毎回変える**方。`K` は事前に安全な経路で配送する必要があるコストの高い値
   だが、`IV` は**秘密である必要がない**ので暗号文と一緒に平文で送れる。
   これにより「鍵配送は1回きり、通信は何度でも」が成立する。
2. `P ⊕ C = P ⊕ (P ⊕ Z) = Z`、すなわち**そのメッセージ位置のキーストリームが丸ごと分かる**。
   同じ `K`・`IV` で暗号化された別の暗号文があれば、その同じ位置を即座に復号できる。
   さらに `Z` が分かれば、攻撃者は任意の偽平文 `P′` に対し `C′ = P′ ⊕ Z` を作れる
   —— つまり**改ざんも自由**（だから実運用では MAC / AEAD を併用する）。
3. 同じ `Z` が2回使われ、`C₁ ⊕ C₂ = P₁ ⊕ P₂` となって鍵が消える。
   [01](./01_vernam-and-otp.md) の **two-time pad** とまったく同じ失敗。
   CTR / GCM モードでの nonce 再利用が破局的なのも同じ理由
   （[`../../02_symmetric-crypto/README.md`](../../02_symmetric-crypto/README.md) を参照）。

</details>
