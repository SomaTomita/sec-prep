# 脅威ランドスケープ（誰が・どれだけ攻撃しているか）

> 対応: プログラム全体 ｜ 層: 地図 (Layer 0)

**この1ページで分かること**

- 攻撃者の5分類と、それぞれの「見えやすさ」の違い
- システムの複雑性がなぜ脆弱性の量に直結するか

- 公表されるサイバー犯罪の損害額をどう読むか（桁の妥当性チェック）

## 一言で

技術を学ぶ前に「**誰が、どれくらいの規模で、何のために攻撃しているか**」の縮尺を持っておく。
この地図が無いと、個々の攻撃手法を学んでも優先順位が付けられない。

> 「脅威・脆弱性・リスク」という**語の定義とリスク計算**は
> [`../06_systems-security/01_security-fundamentals.md`](../06_systems-security/01_security-fundamentals.md) が本体。
> 本ファイルはその上位にある**マクロな環境と実数**を扱う。

## 攻撃者の5分類

同じ「攻撃者」でも動機と**見られたいかどうか**が決定的に違う。可視性の差が、検知の難しさをそのまま決める。

| 分類 | 動機 | 可視性 | 特徴 |
|---|---|---|---|
| ハッカー / セキュリティ研究者 | 技術的興味・名声・報酬 | **見せたい** | 多くは職業化した。ペネトレーションテスト事業者・バグバウンティ参加者 |
| 組織犯罪 | 金銭 | 隠れたい | 物理的な銀行強盗から移行した。ランサムウェアが主力 |
| 内部者 | 金銭・報復・過失 | 正規の権限を持つため**そもそも異常に見えない** | 権限内の行動なので技術的検知が最も難しい |
| 国家 | 諜報・妨害・経済的優位 | **絶対に隠れたい** | 資金と時間の制約が事実上ない。検知されないこと自体が目的の一部 |
| アクティビスト | 主張の可視化 | **見せたい** | 攻撃そのものより注目を集めることが目的 |

**実務上の含意**: 「攻撃が検知されていない」は「攻撃されていない」を意味しない。
最も危険な2分類（国家・内部者）は、いずれも**見えないことを目指している**。

## 複雑性が脆弱性を生む

守るべき対象が指数的に複雑になったことが、この分野の前提条件を変えた。

```
コード規模の推移（おおよその桁）
  1980年代のスペースシャトル        約 40 万行
  現代のデスクトップ OS          5,000 万 〜 1 億行
  現代の自動車（全ECU 合計）        1 億行超
```

行数が増えれば欠陥の絶対数が増え、欠陥の一部は必ず致命的になる。
**「バグ密度を一定に保つ」だけでは、脆弱性の総数は規模とともに増え続ける。**

接続される機器の数も同じ方向に効く。インターネットに接続された機器のうち、
**人が直接操作する端末（PC・スマートフォン）は少数派**で、大半は組込機器である。
つまり「利用者が気をつける」ことで守れる範囲は、全体のごく一部でしかない。

> それに対する**規制的な介入**は [`../07_legal/03_regulatory-tsunami.md`](../07_legal/03_regulatory-tsunami.md) を参照。

## 予防から検知へ：25年の重心移動

セキュリティ対策は「予防 → 検知 → 対応 → 復旧」の4段階で語られる。
過去25年で、**現場の重心は明確に右へ移った**。

```mermaid
flowchart LR
    P["予防<br/>Prevent"] --> D["検知<br/>Detect"] --> R["対応<br/>Respond"] --> Rec["復旧<br/>Recover"]
    style P stroke-dasharray: 5 5
    style D stroke-width:3px
    style R stroke-width:3px
```

**なぜ移動したか**: 上で見た複雑性に、予防のコストが負けた。
数千万行のコードを「欠陥ゼロで書く」ことは経済的に成立しない。

**移動の帰結**: 検知には「見張る人」が要る。人件費を下げるためにオフショア化が進み、
それも限界に達すると**分析の自動化**へ向かった。現在それが AI と呼ばれている
（→ [`05_ai-and-security.md`](05_ai-and-security.md)）。

**代償**: 検知に寄せるということは、**すべてを観測する**ということでもある。
「見えない機器は守れない」という論理は、そのまま全数監視の正当化に使える。
守るための監視と、監視のための監視の境界は技術だけでは引けない。

> SOC の運用・インシデント対応の実務は
> [`../08_management-governance/02_security-operations.md`](../08_management-governance/02_security-operations.md) が本体。

## 損害額の桁を検算する

この分野には**桁が信用できない数値**が大量に流通している。読み方を先に身につけておく。

流通している最大級の推計は「サイバー犯罪の被害は年間 **10.5 兆ドル**」というもの
（Cybersecurity Ventures の予測として引用されることが多い）。
これを、独立に確認できる2つのアンカーと比べる。

| アンカー | 規模（2026年） | 10.5兆ドルとの比 |
|---|---|---|
| 世界の IT 支出**全体** | 約 **6.37 兆ドル** | 損害が IT 支出の **約1.6倍** |
| 世界の情報セキュリティ支出 | 約 **2,120 億ドル** | 損害がセキュリティ産業の **約50倍** |

**含意**: 「世界中の IT 投資を全部足した額より大きい損害が毎年出ているのに、
対策には損害の2%しか使われていない」ことになる。**この状態は経済的に成立しない。**
損害が本当にその規模なら、防御への投資はとうに桁違いに増えているはずである。

### なぜこういう数字が生まれるのか

Florêncio & Herley (2011) が調査手法の問題として整理している。要点は**損害が極端に偏っている**こと。

```
N=1000 人の調査で、1人が「5万ドルの被害」と回答したとする
  → 母集団全体に外挿すると 100 億ドル規模の推計が出る
  → 推計のほぼ全体が、たった1件の未検証の自己申告で決まっている
```

代表的な標本を取っても、**損害については代表的にならない**。
少数の極端な回答が平均を支配し、しかもその回答は検証されていない。

### 教訓

- **規制文書のプリアンブルにもこの種の数値が引用される。** 出典が権威的でも桁は保証されない
- 数値を見たら**独立したアンカーと比べて桁を検算する**癖をつける
- 同じ構造の問題が AI の能力評価にも現れる（→ [`05_ai-and-security.md`](05_ai-and-security.md)）

## 国家アクターとハイブリッド戦

過去15年で、サイバー攻撃は**物理的な影響を伴う国家の手段**になった。

| 事案 | 標的 | 特徴 |
|---|---|---|
| Stuxnet | 産業用制御システム | マルウェアが**物理的な設備を破壊**しうることを実証した |
| ウクライナの電力網攻撃 | 重要インフラ | 停電という形で市民生活に直接影響した |
| SolarWinds | ソフトウェア更新の配布経路 | **サプライチェーン**を経由して多数の組織へ同時に到達した |
| NotPetya | 会計ソフトの更新経路 | 標的国の外へ広く波及し、**民間企業に巨額の被害**が出た |
| Salt Typhoon | 通信事業者 | 通信の傍受基盤そのものへの侵入 |

**共通する構造**:

- **帰属 (attribution) が難しい** — マルウェアは奪って再利用できる。他者の道具を使えば痕跡は他者を指す
- **国境が意味を持たない** — 物理的に渡航せずに越境し、影響を与えられる
- **民間が巻き込まれる** — 標的が国家でも、被害は民間インフラに出る
- **戦争と平時の境界が曖昧** — 「公然の戦争」を宣言せずに実行できる領域になっている

> 攻撃の帰属や国家の関与を評価するときは、**公開情報の多くが当事国の主張である**ことに注意する。
> 本ノートは事案の存在と構造の記述にとどめ、帰属の断定はしない。

## ゼロデイ市場

未公開の脆弱性には市場がある。**発見者のインセンティブがどこを向くか**が問題の核心。

```
脆弱性を見つけた人の選択肢
  ① ベンダーに報告する          → バグバウンティ（数千〜数十万ドル）
  ② 仲介業者・政府機関に売る     → ①より桁違いに高いことがある
  ③ 自分で使う / 犯罪market へ   → さらに高いが違法
```

**緊張**: 民主国家の法執行機関・情報機関もこの市場の買い手である。
つまり**同じ政府が、防御を求めながら攻撃手段を購入している**。
脆弱性を買って保持することは、その脆弱性を自国の市民が使う製品に残すことでもある。

> 攻撃ツールを販売する企業の事例と、その民主的統制の問題は
> [`../07_legal/`](../07_legal/index.md) と [`../03_privacy/`](../03_privacy/index.md) が扱う。
