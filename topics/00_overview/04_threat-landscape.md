# 脅威ランドスケープ（誰が・どれだけ攻撃しているか）

> 対応: プログラム全体 ｜ 層: 地図 (Layer 0)

**この1ページで分かること**

- 攻撃者の 5 分類と「見えたいか隠れたいか」の違い
- 予防から検知へ重心が移った理由と、その代償（全数監視）
- 流通する損害額の桁を検算する方法

技術を学ぶ前に「誰が・どれくらい・何のために」攻撃しているかの縮尺を持つ。縮尺がないと手法を学んでも優先順位が付けられない。

## 最小の例：1 件のインシデントを 5 本柱に当てる

SolarWinds 事件（ソフトウェア更新の配布経路に細工され、更新を入れた多数の組織が同時に侵入された）を分解する。

| 柱 | この事件で問われたこと |
|---|---|
| 暗号 | 更新ファイルの署名（本物だと証明する印）は破られていないのに侵入された |
| ソフトウェア | 開発・ビルド環境そのものが攻撃面だった |
| システム | 侵入後の横展開を誰も検知できなかった |
| プライバシー / 法務 | 被害組織の通知義務・帰属（誰がやったか）の判断 |
| HW | 信頼の起点（root of trust）を更新経路より下に置く必要 |

「更新は正規のもの」という前提が崩れると、5 本柱すべてに問いが立つ。以下はこの縮尺を一般化したもの。

> 「脅威・脆弱性・リスク」の**定義とリスク計算**は [`../06_systems-security/01_security-fundamentals.md`](../06_systems-security/01_security-fundamentals.md) が本体。本ファイルはマクロな環境と実数。

## 攻撃者の 5 分類

| 分類 | 動機 | 可視性 | 特徴 |
|---|---|---|---|
| ハッカー / 研究者 | 技術的興味・名声・報酬 | **見せたい** | ペネトレーションテスト（依頼を受けて行う模擬攻撃）事業者・バグバウンティ（脆弱性報告への報奨金）参加者として職業化 |
| 組織犯罪 | 金銭 | 隠れたい | ランサムウェア（データを暗号化し身代金を要求）が主力 |
| 内部者 | 金銭・報復・過失 | **異常に見えない** | 正規の権限内で動くので技術的検知が最難 |
| 国家 | 諜報・妨害・経済的優位 | **絶対に隠れたい** | 資金と時間の制約が事実上ない |
| アクティビスト | 主張の可視化 | **見せたい** | 攻撃より注目が目的 |

**含意**: 「検知されていない」≠「攻撃されていない」。最も危険な 2 分類（国家・内部者）は見えないことを目指す。

## 複雑性が脆弱性を生む

```
コード規模（おおよその桁）
  1980年代のスペースシャトル   約 40 万行
  現代のデスクトップ OS       5,000 万 〜 1 億行
  現代の自動車（全 ECU 合計）  1 億行超      ← ECU: 車載の制御コンピュータ
```

行数が増えれば欠陥の絶対数が増え、一部は必ず致命的になる。バグ密度を一定に保っても**総数は規模とともに増える**。

接続機器も同じ方向に効く。ネット接続機器のうち人が直接操作する端末は少数派で、大半は組込機器（IoT）。「利用者が気をつける」で守れる範囲はごく一部。

> IoT 市場が安全にならない**経済的理由**は [`../08_management-governance/03_certification-economics.md`](../08_management-governance/03_certification-economics.md)、**規制的介入**は [`../07_legal/03_regulatory-tsunami.md`](../07_legal/03_regulatory-tsunami.md)。

## 予防から検知へ：25 年の重心移動

```mermaid
flowchart LR
    P["予防 Prevent"] --> D["検知 Detect"] --> R["対応 Respond"] --> Rec["復旧 Recover"]
    style P stroke-dasharray: 5 5
    style D stroke-width:3px
    style R stroke-width:3px
```

| 論点 | 内容 |
|---|---|
| なぜ移動したか | 数千万行を欠陥ゼロで書くことは経済的に成立せず、予防のコストが複雑性に負けた |
| 帰結 | 検知には「見張る人」が要る → オフショア化 → 限界 → 分析の自動化（今は AI と呼ばれる。→ [05](05_ai-and-security.md)） |
| 代償 | 検知に寄せる＝**すべてを観測する**。「見えない機器は守れない」は全数監視の正当化に使える |

> SOC（Security Operations Center: 24 時間の監視・対応チーム）の実務は [`../08_management-governance/02_security-operations.md`](../08_management-governance/02_security-operations.md)。

## 損害額の桁を検算する

「サイバー犯罪の被害は年間 **10.5 兆ドル**」（Cybersecurity Ventures の予測として引用されがち）を、独立に確認できる 2 つのアンカーと比べる。

| アンカー | 規模（2026年） | 10.5 兆ドルとの比 |
|---|---|---|
| 世界の IT 支出**全体** | 約 **6.37 兆ドル** | 損害が IT 支出の **約 1.6 倍** |
| 世界の情報セキュリティ支出 | 約 **2,120 億ドル** | 損害がセキュリティ産業の **約 50 倍** |

「IT 投資の全額より大きい損害が毎年出ているのに、対策には損害の 2% しか使われていない」ことになる。**経済的に成立しない。**

### なぜこういう数字が生まれるか

Florêncio & Herley (2011): 損害が極端に偏っているのが原因。

```
N=1000 人の調査で 1 人が「5 万ドルの被害」と回答
  → 母集団に外挿すると 100 億ドル規模の推計
  → 推計のほぼ全体が、たった 1 件の未検証の自己申告で決まる
```

代表的な標本でも、**損害については代表的にならない**。

### 教訓

- 規制文書のプリアンブル（前文）にもこの種の数値が引用される。出典が権威的でも桁は保証されない
- 数値を見たら独立アンカーと比べて桁を検算する
- 同じ構造が AI の能力評価にも現れる（→ [05](05_ai-and-security.md)）

## 国家アクターとハイブリッド戦

| 事案 | 標的 | 特徴 |
|---|---|---|
| Stuxnet | 産業用制御システム | マルウェアが**物理設備を破壊**しうることを実証 |
| ウクライナ電力網攻撃 | 重要インフラ | 停電として市民生活に直接影響 |
| SolarWinds | 更新の配布経路 | **サプライチェーン**（部品や更新の供給網）経由で多数の組織へ同時到達 |
| NotPetya | 会計ソフトの更新経路 | 標的国の外へ波及し民間に巨額の被害 |
| Salt Typhoon | 通信事業者 | 通信の傍受基盤そのものへ侵入 |

| 共通構造 | 意味 |
|---|---|
| 帰属 (attribution) が難しい | マルウェアは奪って再利用できる。他者の道具なら痕跡は他者を指す |
| 国境が意味を持たない | 渡航せずに越境し影響を与える |
| 民間が巻き込まれる | 標的が国家でも被害は民間インフラに出る |
| 戦争と平時の境界が曖昧 | 宣戦せずに実行できる |

> 公開情報の多くは**当事国の主張**。本ノートは事案の存在と構造の記述にとどめ、帰属を断定しない。

## ゼロデイ市場

ゼロデイ＝ベンダーも知らない未公開の脆弱性。発見者の選択肢に市場がある。

```
① ベンダーに報告          → バグバウンティ（数千〜数十万ドル）
② 仲介業者・政府機関に売る → ① より桁違いに高いことがある
③ 自分で使う / 犯罪市場    → さらに高いが違法
```

**緊張**: 民主国家の法執行・情報機関もこの市場の買い手。同じ政府が防御を求めながら攻撃手段を購入し、買った脆弱性は自国市民の製品に残る。

> 攻撃ツール販売企業と民主的統制は [`../07_legal/`](../07_legal/index.md)・[`../03_privacy/`](../03_privacy/index.md)。
