# 04. 鍵長と安全性の直感

> 親: [README](./README.md) ｜ 前: [03 完全秘匿とOTP](./03_perfect-secrecy-otp.md) ｜ 層: 基礎(Layer 1)

OTP は理想だが鍵を使い捨てにできない実用暗号では、「攻撃者が鍵を**総当たり**で
探すのにどれだけかかるか」で安全性を測る（計算量的安全性）。鍵の bit 数がそのまま
探索空間の広さになる。

---

## 総当たり探索空間：bit数 vs 候補数

| 鍵長 | 候補数 (2^n) | 近似値 | 例 |
|---|---|---|---|
| 56 bit | 2^56 | ≈ 7.2 × 10^16 | DES（現在は非推奨） |
| 128 bit | 2^128 | ≈ 3.4 × 10^38 | AES-128 |
| 256 bit | 2^256 | ≈ 1.2 × 10^77 | AES-256 |

1 bit 増えるごとに候補数は **2倍**。56→128の72bit差だけで候補数は
`2^72 ≈ 4.7 × 10^21` 倍に膨れ上がる。

---

## なぜ128bitは（現状）現実的に破れないか

仮に 1秒間に10^18回（現実離れした超高速なASIC群を想定）鍵を試せるとしても、

```
3.4×10^38 個 ÷ 10^18 回/秒 ≈ 3.4×10^20 秒 ≈ 1.1×10^13 年
```

これは宇宙年齢（約138億年 = 1.38×10^10 年）の **約780倍**。1bitで探索空間が
倍になる作りのおかげで、鍵長を線形に増やすだけで探索コストは指数関数的に効く。
これが「128bit以上を選べばまず総当たりは通らない」という直感の根拠。256bitは
さらに桁違いに余裕を持たせた選択。

---

## 一言だけ min-entropy

Shannon エントロピー `H(X)` は「平均的な当てにくさ」だが、安全性の議論では
**攻撃者が一発勝負で当てる確率**の方が重要になることがある。それを測るのが
**min-entropy**:

```
H_∞(X) = -log2( max_x P(x) )
```

01 の偏ったコイン例（`P(表)=0.9`）で比べると:

```
Shannon:     H(X) ≈ 0.469 bit
min-entropy: H_∞(X) = -log2(0.9) ≈ 0.152 bit
```

min-entropy の方が小さい（＝攻撃者にとって有利）。鍵やパスワードの強度を語るときは
「平均的な当てにくさ」より「一番当てやすい値をどれだけ引きやすいか」の方が
安全性評価としては保守的で適切なことが多い。

---

## 演習（解答つき）

1. `2^40` の近似値を求め、`2^128` と比べて何桁違うか（オーダーの差）を答えよ。
2. 攻撃者が1秒間に10^12回試せるとして、128bit鍵を総当たりし尽くすのに
   何年かかるか（オーダーで）求めよ。
3. `P(表)=0.5` の公平コインについて `H_∞(X)` を求め、Shannon エントロピー
   `H(X)=1 bit` と比較せよ。

<details><summary>解答</summary>

1. `2^40 ≈ 1.1×10^12`。`2^128 / 2^40 = 2^88 ≈ 3.1×10^26` → 約26桁（10^26倍）違う。
2. `3.4×10^38 ÷ 10^12 ≈ 3.4×10^26 秒`。1年 ≈ 3.15×10^7秒なので
   `3.4×10^26 / 3.15×10^7 ≈ 1.1×10^19 年`。宇宙年齢より遥かに大きい。
3. `H_∞(X) = -log2(0.5) = 1 bit`。公平コインでは最頻値も1/2しかないので
   Shannon エントロピーと min-entropy が一致する（分布が一様なときの特徴）。

</details>
