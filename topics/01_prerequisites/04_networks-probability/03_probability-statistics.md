# 確率・統計の基礎

> 対応科目: Privacy Technologies, Cryptography and Network Security ｜ 前: [02 ネットワークサービス](./02_network-services.md) ｜ 次: [02_cryptography](../../02_cryptography/index.md) ｜ 層: 基礎(Layer 1)

## 一言で

確率論は「どれくらい起きにくいか」を定量化するツールであり、
暗号の安全性（衝突確率・鍵空間の大きさ）とプライバシー技術（差分プライバシー）の
両方の理論的基盤になる。誕生日パラドックスはハッシュ衝突攻撃の直感を与える典型例。

**この1ページで分かること**

- ベイズの定理と「ベースレートの誤謬」——検知率99%の IDS でも警告の多くが誤検知になる理由
- 誕生日パラドックスが、なぜ n ビットのハッシュを `2^(n/2)` 回で衝突させられるかを説明すること
- 差分プライバシーやエントロピー（鍵強度）が確率論の言葉で定義されること

## 押さえる概念

### 確率の基礎

- **標本空間** Ω: ありえる全結果の集合。
- **事象** A ⊆ Ω、**確率** P(A) ∈ [0, 1]。
- **公理**: P(Ω) = 1、排反事象の加法性。
- **余事象**: P(Ā) = 1 − P(A)。「少なくとも1回起きる」計算で頻用。

### 条件付き確率とベイズの定理

- **条件付き確率**:
  ```
  P(A | B) = P(A ∩ B) / P(B)    （P(B) > 0）
  ```
- **ベイズの定理**:
  ```
  P(A | B) = P(B | A) · P(A) / P(B)
  ```
  - 事前確率 P(A) と尤度 P(B|A) から事後確率 P(A|B) を更新する枠組み。
  - セキュリティ応用: マルウェア検知（スパムフィルタ）、侵入検知の偽陽性/偽陰性分析。

#### 計算例: 侵入検知システム（IDS）の警告は信用できるか

```
前提: P(悪意)=0.001（全トラフィックの0.1%が実際に悪意）
      P(警告|悪意)=0.99（真陽性率）  P(警告|正常)=0.05（偽陽性率）

P(警告) = 0.99×0.001 + 0.05×0.999 = 0.00099 + 0.04995 = 0.05094

P(悪意|警告) = 0.00099 / 0.05094 ≈ 0.0194 ≈ 1.9%
```

検知率99%の IDS でも警告のうち実際に悪意があるのは約2%のみ——事前確率が低いほど誤検知が支配的になる（**ベースレートの誤謬**）。

### 主要な確率分布

| 分布 | パラメータ | 主なセキュリティ応用 |
|---|---|---|
| 一様分布 | — | 鍵生成・乱数（全値が等確率）|
| ベルヌーイ / 二項分布 | p, n | ビット反転誤り、試行の繰り返し |
| 幾何分布 | p | 初めて衝突するまでの試行回数 |
| 正規分布 | μ, σ | サイドチャネル測定値のモデル化 |
| ポアソン分布 | λ | 単位時間あたりの攻撃到着数 |

### 期待値と分散

- **期待値**: E[X] = Σ x · P(X = x)（平均）。
- **分散**: Var(X) = E[(X − E[X])²]（散らばり）。
- **標準偏差** σ = √Var(X)。
- 暗号解析での意味: サイドチャネル攻撃で電力波形のノイズ（分散）と信号（期待値のずれ）を統計的に分離する。

### 乱数と疑似乱数（PRNG）

- **真の乱数（TRNG）**: 物理的エントロピー源（熱雑音、量子効果）から生成。
- **疑似乱数生成器（PRNG）**: 決定論的アルゴリズム。シードが同じなら同じ列を生成。
- **暗号論的 PRNG（CSPRNG）**: 出力列から次ビットを予測計算困難。
  - 条件: 前方安全性（シードが漏れても過去の出力を再現できない）。
  - 例: Linux の `/dev/urandom`（ChaCha20ベース）、CTR-DRBG（NIST SP 800-90A）。
- **弱い PRNG の危険性**: 線形合同法 PRNG を暗号用途に使うと状態推測攻撃を受ける。
  Debian OpenSSL 乱数バグ（2008年）は CSPRNG の誤実装で SSH 鍵が予測可能になった実例。

### 誕生日パラドックスと誕生日攻撃

- **誕生日問題**: n 人の中に同じ誕生日の組が存在する確率が 50% を超えるのは何人か？
  ```
  約 n ≈ √(2 ln 2) · √N ≈ 1.1774 · √N   （N = 365 のとき n ≈ 23）
  ```
- **一般化**: N 個の値域から t 個をランダム選択したとき、衝突確率が 1/2 を超えるのは同じく `t ≈ √(2 ln 2)·√N ≈ 1.1774·√N`（係数は 1 − e^{−t(t−1)/(2N)} = 1/2 を解いた値。概算では 1.18 とも書かれる）。

#### 計算トレース: 23人で衝突確率が50%を超えることの確認

```
P(衝突なし) = 365/365 × 364/365 × 363/365 × … × 343/365   （365 から 343 まで、23項の積）
```

| 人数 n | この時点で掛ける項 | 累積 P(衝突なし) |
|---|---|---|
| 5 | 361/365 | 0.9729 |
| 10 | 356/365 | 0.8831 |
| 15 | 351/365 | 0.7471 |
| 23 | 343/365 | **0.4927** |

`P(衝突) = 1 − 0.4927 ≈ 0.5073` → **約50.7%**。近似式 `1.1774×√365 ≈ 22.5` が示す通り23人が境目。

- **ハッシュへの応用**:
  - 上と同じ式を、ハッシュの出力空間 `N = 2^n` に当てはめると、衝突確率が50%を超える試行回数は
    `t ≈ 1.1774×√(2^n) ≈ 2^(n/2)` （オーダーで見れば）。
  - **128ビットハッシュ**（N=2^128）: 必要な試行回数は 2^128 では**なく** `2^64` で済む——出力長は欲しい安全性の2倍必要という設計指針（SHA-256採用の根拠）の由来。
  - SHA-1（160ビット）: 誕生日境界 2^80 → 2017年に実際に衝突が発見（SHAttered）。
  - SHA-256（256ビット）: 誕生日境界は 2^128。現在の計算資源では到達不可能。
- **MAC/署名への影響**: セキュリティパラメータ n を選ぶとき、誕生日境界 2^(n/2) を脅威モデルに含める必要がある。

### 情報理論との接点（エントロピー）

- **シャノンエントロピー**:
  ```
  H(X) = − Σ P(x) · log₂ P(x)     [ビット]
  ```
  - 一様分布で最大: n 通りの選択肢 → H = log₂(n) ビット。
  - 偏った分布ほど低い（予測しやすい）。
- **鍵強度との接続**: 128ビットキーは H = 128ビット（真に一様なら）。パスワードの「エントロピー」はこの文脈で使われる。
- 詳細は `../01_math-for-crypto/05_info-theory/README.md` を参照。

### 差分プライバシーとの接続

プライバシー技術の中心概念「差分プライバシー（DP）」は確率論で定義される。

- **ε-差分プライバシー**:
  ```
  P[M(D) ∈ S] ≤ e^ε · P[M(D') ∈ S]    （任意の隣接データセット D, D' と出力集合 S）
  ```
  - M はランダムアルゴリズム（乱数が必須）。ε が小さいほどプライバシーが強い。
  - **ラプラス機構**: 感度 Δf に対して Lap(Δf/ε) のノイズを加算。
  - 確率分布の知識なしにこの定義は読めない。

## なぜ重要か / コースでの位置づけ

**Privacy Technologies**
- 差分プライバシー・k-匿名化の「なぜこれで安全か」の論証は全て確率論で行われる。
- 前提として「確率・統計・情報理論」が明示されている（シラバス §6.4）。

**Cryptography and Network Security**
- 暗号解読の計算量論的安全性（確率ネゲリジブル関数など）は確率論の言葉で定義される。
- 誕生日境界はハッシュ関数・MAC の出力長設計の根拠。

**Advanced Methods in Cryptography**
- 差分解読（Differential Cryptanalysis）と線形解読（Linear Cryptanalysis）は確率的議論。差分と線形特性の確率を積み重ねて攻撃計算量を見積もる。

**統計的攻撃**
- サイドチャネル攻撃（電力差分解析 DPA）: 複数トレースの平均を使い信号と雑音を分離。
- 平均・分散・相関係数の理解が前提。

## 演習（解答つき）

1. 1年が365日ではなく**1000日**だったら、衝突確率が50%を超えるのは何人からか。近似式で見積もり、境目付近の値も確認せよ。
2. 256ビットハッシュ関数（SHA-256）の誕生日境界（衝突に必要な試行回数のオーダー）はいくつか。
3. IDS の計算例で事前確率 P(悪意) を 0.001 から **0.01**（10倍）に上げると、P(悪意|警告) はどう変わるか計算せよ。

<details><summary>解答</summary>

1. 近似式 `1.1774×√1000 ≈ 37.2` → 38人前後が境目。実際に積を計算すると
   `n=37`: P(衝突) ≈ 49.05%（50%未満）、`n=38`: P(衝突) ≈ 50.93%（50%超）。
   よって **38人**から過半数を超える。365日の場合（23人）よりずっと多く必要になる——
   母集団 N が大きいほど必要な人数は `√N` で緩やかにしか増えない、という誕生日パラドックスの直感通り。
2. `2^(256/2) = 2^128`。これが SHA-256 の「128ビット安全性」という表現の根拠（2^256 ではない）。
3. `P(警告) = 0.99×0.01 + 0.05×0.99 = 0.0594`、`P(悪意|警告) = 0.0099/0.0594 ≈ 0.1667 ≈ 16.7%`。
   事前確率が10倍になると事後確率は約1.9%→約16.7%に跳ね上がる（ベイズ更新は prior に敏感）。

</details>
