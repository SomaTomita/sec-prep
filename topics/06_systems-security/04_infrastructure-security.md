# 04. インフラセキュリティ

**この1ページで分かること**

- ファイアウォールの4方式と「デフォルト拒否」ルールの実装
- IDS/IPS（侵入検知/防御システム）の2つの検知方式とそれぞれの弱点
- 境界防御（DMZ）からゼロトラスト（暗黙の信頼を排除する設計）への移行と、その背景

ここまでは「1台の中で誰が何をしてよいか」。ここからはネットワーク全体で「どの通信を通し、どの侵入を検知し、被害をどう閉じ込めるか」——建物の門番・監視カメラ・区画分けにあたる。
前提は [`../01_prerequisites/04_networks-probability/`](../01_prerequisites/04_networks-probability/index.md) の TCP/IP。

## 最小の例：3行のファイアウォールルール

```
許可: 送信元 any          宛先 10.0.0.5:443   ← 誰でも HTTPS だけは通す
許可: 送信元 10.0.0.0/24  宛先 10.0.0.5:22    ← SSH は社内からだけ
拒否: それ以外すべて                          ← 書いていない通信は落とす
```

3行目が **デフォルト拒否**（[01](./01_security-fundamentals.md) のフェイルセーフ原則の実装）。ルールを書き漏らしても「危険な通信が通る」側には倒れない。以下の方式の違いは「1〜2行目を何を見て判定するか」の違い。

## ファイアウォール

NIST SP 800-41 Rev.1 の分類:

| 方式 | 何を見て判定するか | 長所/短所 |
|---|---|---|
| パケットフィルタ | ヘッダ（IP・ポート番号）のみ | 高速だが状態を見ないので偽装に弱い |
| ステートフルインスペクション | コネクションの状態（TCP の SYN/ACK 等） | 「確立済み通信への応答」を正しく通せる。現在の主流 |
| アプリケーション層（プロキシ） | HTTP 等の中身まで | 精度は高いが重い。プロトコルごとに対応が要る |
| NGFW（次世代 FW） | 上記＋アプリ識別・侵入防御 | 実質 IDS/IPS と統合 |

---

## IDS/IPS（侵入検知/防御システム）

NIST SP 800-94 の分類:

| | IDS (Intrusion Detection) | IPS (Intrusion Prevention) |
|---|---|---|
| 検知時 | アラートを出す（通信は止めない） | その場で遮断する |

| 検知方式 | 仕組み | 弱点 |
|---|---|---|
| シグネチャベース | 既知の攻撃パターン（バイト列・正規表現）と照合 | 未知の攻撃（ゼロデイ）を検知できない |
| 異常検知ベース | 平常時からの統計的逸脱を検出 | 誤検知（false positive）が多い |

Martin Roesch (1999) の **Snort** はシグネチャベースの代表的 OSS。ルールの概念形:

```
alert tcp any any -> 10.0.0.5 80 (content:"' OR '1'='1"; msg:"Possible SQLi";)
```

[02](./02_software-vulnerabilities.md) の Injection を、アプリ側とは別の層（ネットワーク）で検知する多層防御の一例。

## ネットワークセグメンテーションとゼロトラスト

```mermaid
flowchart LR
    NET["インターネット"] --> FW1["FW"]
    FW1 --> DMZ["DMZ（公開サーバ群）"]
    DMZ --> FW2["FW"]
    FW2 --> LAN["社内 LAN"]
```

| | 境界防御（DMZ） | ゼロトラスト（NIST SP 800-207, 2020） |
|---|---|---|
| 前提 | 境界の内側は信頼できる | 位置による暗黙の信頼を排除 |
| 仕組み | 公開サーバを DMZ（非武装地帯）に置き、内部 LAN との間にもう1段 FW。VLAN（スイッチ上の論理分割）も同目的 | すべての要求を、位置に関係なくアイデンティティ・端末状態・文脈で毎回検証 |
| 崩れた理由 | リモートワーク・BYOD（私物端末の業務利用）・クラウドで「内側」が曖昧に | — |

[03](./03_authn-authz-access-control.md) の ABAC は「毎回の要求を属性で判定する」発想が共通し、ゼロトラストの認可エンジンとして自然に組み合わさる。

---

## なぜ重要か / コースでの位置づけ

FW/IDS/IPS は [02](./02_software-vulnerabilities.md) の脆弱性が突かれた**後**の検知・遮断を担い、[03](./03_authn-authz-access-control.md) の認可モデルはゼロトラストの中核になる。「アプリを完璧に直す」と「ネットワークで多層に守る」は代替ではなく両輪。

## 演習（解答つき）

1. ステートフルインスペクション型ファイアウォールが、単純なパケットフィルタ型より
   優れている点を一言で述べよ。
2. シグネチャベースIDSが未知の攻撃を検知できない理由を述べよ。
3. ゼロトラストアーキテクチャが「社内LANにいるから安全」という前提を排除する理由を、
   リモートワーク普及と絡めて説明せよ。

<details><summary>解答</summary>

1. パケットフィルタは各パケットを独立にヘッダだけで判定するが、ステートフルはコネクションの状態を追跡できるため、「確立済み通信への正当な応答」と「なりすましの新規パケット」を区別できる。
2. 既知パターンとの照合でしか検知できないため、一致するシグネチャが存在しない新種・未公開（ゼロデイ）の攻撃はすり抜ける。
3. リモートワーク・BYOD・クラウドで、正規の利用者・端末が「社内ネットワークの内側」からだけアクセスするとは限らなくなった。位置と信頼の相関が崩れたため、位置に頼らず毎回検証する方式に移行する必要が生じた。

</details>
