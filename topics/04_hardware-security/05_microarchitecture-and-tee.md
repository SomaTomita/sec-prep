# 05. マイクロアーキテクチャ攻撃と TEE

> 前: [04 サイドチャネル](./04_side-channels/README.md) ｜ 層: 基礎(Layer 1)

[04](./04_side-channels/README.md) は物理量（電力・時間）の観測だった。
ここでは物理計測器を使わず、**同じ CPU で動くソフトウェアだけ**で秘密を取る攻撃と、
それに抗するはずだった仕組み（TEE）を見る。

**この1ページで分かること**

- ISW という抽象化が「時間」を規定していないことが、なぜ構造的な漏洩を生むのか
- 分離の水平方向・垂直方向という2軸と、サイドチャネルがそれを迂回する仕組み
- TEE（SGX 等）が守ろうとしたものと、破られたことの意味
- 「定数時間で書けば安全」がもはや十分条件でない理由

---

## 抽象化が規定していないもの

命令セットアーキテクチャ（ISA。x86 / ARM / RISC-V 等）は、
ソフトウェアとハードウェアの間の**契約**である。

| ISA が定義するもの | ISA が定義しないもの |
|---|---|
| 命令の種類と意味 | **各命令の実行時間** |
| 命令のエンコーディング | **消費電力** |
| レジスタの数と幅 | キャッシュの状態変化 |
| メモリモデル | 分岐予測器の内部状態 |

**コンパイラはこの契約を信じて最適化する。** しかし実物はシミュレータではなく
電気で動く回路であり、契約に書かれていない性質——時間・電力・キャッシュ——は
最適化の副産物として自由に変化し、そこから情報が漏れる。

**「速くする最適化」と「観測可能な差を作らない」は原理的に両立しない**——
性能のために状態を共有し、履歴に応じて振る舞いを変えるのが最適化の本質だからである。

---

## 分離の2軸：水平と垂直

OS とハードウェアが協調して作る分離には2つの方向がある。

```
水平方向: プロセス A ｜ プロセス B     ← 同じ特権レベルの相互分離
                ↕
垂直方向: ユーザー空間 / カーネル空間  ← 特権レベル間の分離
```

**サイドチャネルは壁を壊すのではなく、迂回する。**
メモリ保護は「読んではいけない場所を読ませない」ことを保証するが、
**読まずに推測すること**は禁じていない。キャッシュの状態や実行時間は保護の対象外なので、
そこを通れば壁は関係ない。

---

## メモリ安全性を破らない攻撃

従来の脆弱性との違いを押さえておく。

| | バッファオーバーフロー等 | マイクロアーキテクチャ攻撃 |
|---|---|---|
| 何をするか | 境界を**越える** | 境界を**越えない** |
| 破る保証 | メモリ安全性 | （何も破らない。副次的な観測のみ） |
| 効く対策 | メモリ安全な言語・ASLR・スタック保護 | **上記はすべて効かない** |

**Rust に書き換えても、ASLR を入れても防げない。**
攻撃者は許可された操作しか行っておらず、ただ観測しているだけだからである。
つまり**防御の発想がまったく違う**——「不正なアクセスを止める」枠組みでは扱えない。
バッファオーバーフローの本体は
[`../06_systems-security/02_software-vulnerabilities.md`](../06_systems-security/02_software-vulnerabilities.md)。

---

## TEE：OS を信頼しないという発想

通常のセキュリティモデルではアプリは OS を信頼する（OS が壊れたら終わり）。
TEE（Trusted Execution Environment）はその前提を外し、
**OS が乗っ取られていても中のデータを守る**ことを目指す——CPU が OS からもメモリを隠す。
これは [`03_security-building-blocks.md`](./03_security-building-blocks.md) の
Root of Trust を**実行中のプログラム**に拡張したものと言える。

### 現在の位置づけ

Intel SGX が先駆けだったが、**2021年にクライアント向けはデプリケートされ**、
サーバ（Xeon）系に限られるようになった。現在は VM 単位で保護する方式が主流である。

| 技術 | 保護の単位 |
|---|---|
| Intel SGX | プロセス内の一部（エンクレーブ） |
| Intel TDX | 仮想マシン全体 |
| AMD SEV-SNP | 仮想マシン全体 |
| ARM CCA (Realms) | 仮想マシン相当（ARMv9） |

この領域全体を **機密計算 (confidential computing)** と呼ぶ。GPU にも同様の仕組みが
導入されつつあり、「クラウドに預けたデータを事業者にも見せない」という要求に応える技術として
広がっている（[`../07_legal/03_regulatory-tsunami.md`](../07_legal/03_regulatory-tsunami.md)
のデジタル主権とも接続する）。

### 破られた意味

SGX は側チャネル攻撃で複数回破られている（Foreshadow, 2018 等）。
**重要なのは「TEE は無意味」ということではなく、脅威モデルの境界がどこかを知ること。**

```
TEE が守ると主張したもの: 悪意ある OS からのメモリの直接読み出し
TEE が守らなかったもの:   キャッシュ・投機実行を経由した間接的な観測
```

TEE は**脅威モデルを拡大した**（OS を信頼しない）が、
その新しいモデルの中でサイドチャネルを閉じきれていなかった、という構図である。

---

## 投機的実行が定数時間コードを破る

[04](./04_side-channels/01_timing-attacks.md) で「定数時間実装が対策」と書いた。
2018年以降、この前提に但し書きが付いた。

```
定数時間コード: 秘密に依存した分岐を書かない
        ↓
しかし CPU は分岐予測に基づいて「実行されないはずの経路」を投機的に実行する
        ↓
投機実行された経路が秘密依存のメモリアクセスを行えば、キャッシュに痕跡が残る
        ↓
ソースコード上は定数時間でも、実際の実行では漏れる
```

**つまり定数時間性は「書いたコード」ではなく「実際の実行」について要求される性質になった。**
暗号実装者にとって、コンパイラと CPU の両方を疑う必要があるということである。

分岐予測と投機実行の動作原理は
[`../01_prerequisites/03_hardware-digital-logic/03_hdl-and-architecture/02_pipelining-and-hazards.md`](../01_prerequisites/03_hardware-digital-logic/03_hdl-and-architecture/02_pipelining-and-hazards.md)、
Spectre / Meltdown 自体は [`02_hardware-attacks.md`](./02_hardware-attacks.md) が本体。

## 暗号コード以外への影響

サイドチャネルは暗号鍵だけの問題ではない——
**秘密に依存した制御フローやメモリアクセスは、あらゆるプログラムに遍在する。**
controlled-channel attack（Xu–Cui–Peinado, IEEE S&P 2015）は、悪意ある OS が
ページフォルトを観測することで、エンクレーブ内で処理されている
**画像の内容を粗い解像度で復元**しうることを示した。

```
暗号ライブラリ  → 鍵が漏れる
画像処理        → 処理中の画像が漏れる
データベース検索 → 検索条件やヒットしたレコードが漏れる
```

**「暗号を使っていないから関係ない」とは言えない。**
プライバシー影響という観点では [`../03_privacy/`](../03_privacy/index.md) の議論に接続する。

## 演習（解答つき）

1. マイクロアーキテクチャ攻撃が、メモリ安全な言語への書き換えでは防げない理由を述べよ。
2. Flush+Reload が前提とする「共有メモリ」が、攻撃者の特殊な工作なしに
   満たされてしまうのはなぜか（[04](./04_side-channels/03_cache-side-channels.md) の復習）。
3. TEE が「破られた」と報じられたとき、脅威モデルの観点では何が起きたと理解すべきか。

<details><summary>解答</summary>

1. これらの攻撃は**メモリ安全性を破っていない**ため。攻撃者は許可された範囲しか
   アクセスせず境界を越えない。ただキャッシュの状態や実行時間という
   **副次的な情報を観測している**だけである。メモリ安全な言語・ASLR・スタック保護は
   いずれも「境界を越えるアクセス」を防ぐ仕組みなので、越えない攻撃には効かない。
2. 現代 OS はメモリ節約のため**共有ライブラリを複数プロセスに同じ物理ページとして写像する**。
   攻撃者と被害者が同じ暗号ライブラリを使っていれば、そのコードやテーブルは
   物理的に同一ページ上にある。OS の通常の最適化が攻撃の前提条件を用意している。
3. **脅威モデルの境界が想定より狭かった**と理解する。TEE は「悪意ある OS からの
   メモリの直接読み出し」を防ぐという主張自体は満たしており、
   破られたのは新しい脅威モデルの中で**サイドチャネル経由の間接的な観測**を
   閉じきれていなかった部分である。「TEE は無意味」ではなく
   「守る範囲と守らない範囲を区別して使う」のが正しい理解になる。

</details>
