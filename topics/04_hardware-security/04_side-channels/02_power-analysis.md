# 02. 電力解析（SPA・DPA・CPA）

> 親: [README](./README.md) ｜ 前: [01 タイミング攻撃](./01_timing-attacks.md) ｜ 次: [03 キャッシュサイドチャネル](./03_cache-side-channels.md) ｜ 層: 基礎(Layer 1)

実行時間より細かい粒度で漏れるのが**消費電力**である。
[01](./01_timing-attacks.md) は「処理全体が何秒かかったか」を見たが、
電力波形は**処理の途中で何が起きたか**を時間軸に沿って見せる。

---

## なぜ電力が情報を漏らすのか

[`../../01_prerequisites/03_hardware-digital-logic/01_cmos-logic.md`](../../01_prerequisites/03_hardware-digital-logic/01_cmos-logic.md)
の動的消費電力の式を思い出す。

```
P_dynamic ≈ α · C_L · V_DD² · f
```

`α`（ビット遷移の活性化率）が**処理しているデータに依存**する。
0→1 に変わるビットが多ければ電力を多く消費し、変化がなければ消費しない。
つまり**消費電力の波形そのものがデータの関数**になっている。

### 最小の例

インバータ（NOT ゲート）1個で考える。入力が 0→1 に変わるとき出力は 1→0 になり、
負荷容量の充放電が起きて電流が流れる。入力が変わらなければ電流は流れない。

```
入力の遷移あり → 充放電イベントが波形に現れる
入力の遷移なし → 何も現れない
```

回路の入出力を知らなくても、**充放電が起きたかどうかを波形から読めば、
そこで値が変化したことが分かる**。この単純な事実がチップ全体に積み上がる。

## 段階1：SPA（単純電力解析）

波形を**目視**して、実行された命令の違いを直接読み取る。

### RSA への SPA

`m^d mod n` を計算する2乗繰り返し法（[`../../02_cryptography/03_public-key-crypto/01_rsa/02_encryption-decryption.md`](../../02_cryptography/03_public-key-crypto/01_rsa/02_encryption-decryption.md)）は、
指数 `d` のビットを上位から見て次を繰り返す。

```
d のビットが 0 → 2乗のみ
d のビットが 1 → 2乗してから乗算
```

**2乗と乗算の消費電力が違えば**（実装によっては2乗の方が軽い）、
波形の形状から「2乗だけ」と「2乗+乗算」を区別できる。
つまり**指数のビット列＝秘密鍵が、1本の波形から直読できる**。

### 波形からアルゴリズム構造が見える

攻撃の前段として「今どのアルゴリズムのどこを実行しているか」を特定する工程がある。
波形の**粗い繰り返しパターン**を数えれば、ラウンド構造が見えてくる。

```
繰り返しの塊が 10 個 → AES-128（10ラウンド）
繰り返しの塊が 14 個 → AES-256（14ラウンド）
```

ラウンド数から鍵長が分かり、1ラウンド内の構造から
SubBytes / ShiftRows / MixColumns / AddRoundKey の各段が識別できることもある。
**何も知らない状態から始めても、波形が実装を教えてくれる。**

## 段階2：DPA（差分電力解析）

波形1本では読み取れない微小な差を、**大量の波形と統計処理**で暴く（Kocher–Jaffe–Jun, 1999）。

```
1. 鍵の一部（例: 1バイト）について全候補（256通り）を仮定する
2. 各仮定のもとで「ある中間値のビットが 0 か 1 か」を予測し、波形群を2グループに分ける
3. 2グループの平均波形の差を計算する
4. 正しい鍵の仮定のときだけ、その中間値を計算する瞬間に
   はっきりした差（スパイク）が現れる
```

**要点は鍵の分割統治**。鍵全体（AES-128 なら 2¹²⁸ 通り）を当てるのではなく、
**1バイトずつ独立に決められる**ので `256 × 16` 回の検定で済む。
[01](./01_timing-attacks.md) の PIN 攻撃と同じ「指数から線形へ」の構造がここにも現れる。

## 段階3：CPA（相関電力解析）

DPA の単純な差の代わりに、**漏洩モデル**と実測値の**相関係数**を計算する
（Brier–Clavier–Olivier, CHES 2004）。

```
漏洩モデルの仮定:
  消費電力 ∝ ハミング重み（値のビット中の 1 の個数）
         または ハミング距離（遷移したビット数）
```

各鍵候補について「予測される消費電力」を計算し、実測波形との相関を取る。
相関が最も高い候補が正解である。

**なぜ DPA より効率的か**: DPA は「0 か 1 か」の2値でグループ分けするだけだが、
CPA は**電力の大きさそのものを予測**して突き合わせる。使う情報が多いため
統計的な検出力が高く、**より少ない波形数で鍵が復元できる**。

> **ハミング重み/距離モデルは `α`（ビット遷移の割合）を近似したもの**であり、
> 冒頭の物理式と直結している。物理から統計モデルへ、そして攻撃へ——という筋が通っている。

## その他の手法

| 手法 | 考え方 |
|---|---|
| **テンプレート攻撃** | 攻撃対象と同型のデバイスを入手し、既知の鍵で**事前に波形の統計モデルを学習**しておく。本番では少数の波形（理想的には1本）で鍵を特定する。プロファイリングにコストをかけて本番の必要波形数を減らす方向 |
| **内部衝突攻撃** | 計算の**途中**で同じ値が現れる（衝突する）ことを利用する。衝突は出力には現れないが、波形には現れる。「出力を見ても分からないが、途中を見れば分かる」ケース |
| **電磁波解析 (EMA)** | 消費電力の代わりに放射される電磁波を測る。チップ表面の**特定位置**にプローブを当てられるため、電力より局所的な情報が取れる |

## 演習（解答つき）

1. RSA の2乗繰り返し法に対する SPA が成立するために、実装側に必要な性質は何か。
2. DPA で鍵を1バイトずつ独立に決められる理由を述べよ。また AES-128 の鍵全体を
   総当たりする場合と比べて検定回数がどう変わるか。
3. CPA が DPA より少ない波形数で成功する理由を、使っている情報の違いから説明せよ。

<details><summary>解答</summary>

1. **2乗と乗算の消費電力（または実行時間）に観測可能な差があること**。
   指数のビットが 0 のときは2乗のみ、1 のときは2乗+乗算が実行されるため、
   両者が波形上で区別できれば指数のビット列が読める。
   逆に言えば、ビットの値によらず常に同じ演算列を実行する実装
   （モンゴメリ・ラダー等）にすればこの攻撃は成立しない。
2. 攻撃者は**特定の中間値**（例: AES の1ラウンド目の SubBytes 出力の1バイト）を狙う。
   この中間値は**鍵の対応する1バイトだけ**に依存し、他のバイトには依存しない。
   したがって1バイト分（256通り）の仮定を立てれば、その中間値の予測が確定する。
   検定回数は `256 × 16 = 4,096` 回程度で、鍵全体の総当たり `2¹²⁸` とは比較にならない。
3. DPA は中間値のビットが 0 か 1 かで波形を2グループに分け、その**平均の差**を見るだけ。
   一方 CPA はハミング重み等の漏洩モデルから**消費電力の大きさそのものを予測**し、
   実測値との相関係数を計算する。後者は「どのくらい電力を使うか」という
   量的な情報まで活用しているため、同じノイズ環境でも信号を検出しやすく、
   必要な波形数が少なくなる。

</details>
