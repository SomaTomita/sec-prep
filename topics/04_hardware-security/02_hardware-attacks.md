# 02. ハードウェア攻撃と攻撃者能力

> 対応科目: Hardware Security ｜ 前: [01 プラットフォーム設計](./01_digital-platform-design.md) ｜ 次: [03 セキュリティ部品](./03_security-building-blocks.md) ｜ 層: 基礎(Layer 1)

**この1ページで分かること**

- 攻撃者の物理アクセスによる 3 分類：非侵襲的・半侵襲的・侵襲的
- フォールト注入（意図的に計算ミスを起こさせる攻撃）が RSA-CRT の秘密鍵を署名 2 つで暴く仕組み
- ソフトウェアだけの Spectre/Meltdown が投機実行の「キャッシュに残る痕跡」を悪用する構図

金庫の錠前が数学的に完璧でも、金庫そのものにドリルを当てられれば話は別——それがハードウェア攻撃。攻撃者が「どこまで物理的に触れるか」で防御の考え方が変わる。

---

## 最小の例: 計算を 1 回だけ間違えさせる

```
正常:  電源 1.0 V   →  3 × 5 = 15
攻撃:  一瞬 0.7 V   →  3 × 5 = 14   ← 回路が間に合わず 1 ビット化ける
```

「正解 15」と「誤答 14」を並べて比べると、中で使われた値が逆算できる場合がある。これを RSA の署名でやると秘密鍵が出る（後述）。

---

## 攻撃者能力の分類（Skorobogatov & Anderson）

| 分類 | チップへの操作 | 例 | コスト・難易度 |
|---|---|---|---|
| 非侵襲的 (non-invasive) | 分解せず、外部から観測・操作するだけ | 電力波形の測定、タイミング測定（[04](./04_side-channels/README.md)で詳述）、電圧・クロックの外部からの操作 | 低 |
| 半侵襲的 (semi-invasive) | パッケージを開け表面を露出。配線には触れない | レーザー・EM パルス（電磁パルス）の照射でフォールト注入 | 中 |
| 侵襲的 (invasive) | 内部配線に直接接触して読み書き | マイクロプロービング（微細な探針）、FIB（集束イオンビーム）で配線を切断・再配線 | 高。ただし原理上どんな対策も突破しうる |

実用的な攻撃は**安価で再現しやすい非侵襲的・半侵襲的**に集中する。

### 攻撃者は実際にどう進めるか

論文に載るのは最後の 1 手だが、実際は次の順。**どの段階で止めるかが防御の設計判断。**

| 段階 | やること | 防御側の打ち手 |
|---|---|---|
| 1. 入手 | 対象機器を手に入れる。市販されていない業務用機器も中古市場に出回る | 出回る前提で設計する（機器の秘匿に頼らない） |
| 2. 分解・観察 | 基板を見て主要チップとテストポイントを特定する | 重要信号を内層に埋める、テストポイントを残さない |
| 3. インタフェース特定 | ロジックアナライザ（多数の信号線を同時に記録する測定器）で JTAG / SWD / UART（開発用のデバッグ配線）を探す | 出荷時にデバッグポートを恒久無効化 |
| 4. 情報取得 | ファームウェアの吸い出し、ルートシェルの取得 | セキュアブート、フラッシュの暗号化 |
| 5. 物理攻撃 | サイドチャネル観測・フォールト注入・デキャップして配線を追う | 本ファイル以降と [04](./04_side-channels/README.md) の各対策 |

**段階 3 で止まる製品が多い。** 量産品にデバッグ経路やルートシェルが残る例は珍しくない。「物理攻撃は高度な設備が要る」と思うと段階 1〜4 の安さを見誤る。

チップをデキャップ（封止樹脂を剥がす）して層ごとに撮像すれば回路は復元できる。**チップに書き込んだ定数は秘密にならない**——[Kerckhoffs の原理](../02_cryptography/01_goals-and-primitives.md)がハードウェアでも成り立つ理由。

### 受け取った部品が意図した部品とは限らない

| 改変 | 例 | 問題 |
|---|---|---|
| 非意図的 | 在庫切れで互換品に差し替え | ピン配置は同じでも**乱数品質・デバッグ保護・既知脆弱性は別物** |
| 意図的 | 流通経路上での改変 | 受領時に検証する手段が乏しい |

調達プロセスとしての本体は [08 リスク管理](../08_management-governance/01_risk-management.md)。ここでの含意は「**部品表が同じでもセキュリティ特性は同じではない**」。

## フォールト注入攻撃（Fault Injection）

```
アイデア: 電圧/クロックグリッチ（電源やクロックを一瞬乱す）・レーザー・電磁パルスで
  計算途中に「ミス」を起こさせ、誤った出力から秘密鍵を逆算する
```

### 実例：RSA-CRT へのフォールト攻撃（Boneh, DeMillo, Lipton, 1997年）

[RSA-CRT](../02_cryptography/03_public-key-crypto/01_rsa/README.md)（中国剰余定理＝`mod p` と `mod q` を別々に計算して合成する高速化）の**片方だけ**にフォールトを注入すると、素因数がその場で求まる。

```
正しい署名: s ≡ m^d (mod n)
mod p 側にだけフォールトを注入した誤った署名: s'（mod q 側は正しいまま）

このとき s ≡ s' (mod q) だが s ≢ s' (mod p) となるため
gcd(s - s', n) = q が成り立つ！
```

### 数値で確認（[01_rsa](../02_cryptography/03_public-key-crypto/01_rsa/01_key-generation.md) のトイ鍵を流用）

```
n=55, p=5, q=11, e=3, d=7, m=2
正しい署名: s = 18   （検算: 18³ mod 55 = 2 ✓）
mod p 側にフォールトを注入した誤った署名: s' = 29

gcd(s - s', n) = gcd(18-29, 55) = gcd(11, 55) = 11 = q   ← qがそのまま求まった！
```

**正しい署名 1 つ＋誤署名 1 つ**で `n` が分解され秘密鍵が漏れる。[RSA の数学](../02_cryptography/03_public-key-crypto/01_rsa/03_correctness-proof.md)は正しいまま、**物理的な妨害**だけで破られる典型例。

**対策**: 署名後に `s^e mod n =? m` を検算し不一致なら破棄、冗長計算で照合。

## Spectre / Meltdown（2018年1月公開）

[`../01_prerequisites/03_hardware-digital-logic/03_hdl-and-architecture/02_pipelining-and-hazards.md`](../01_prerequisites/03_hardware-digital-logic/03_hdl-and-architecture/02_pipelining-and-hazards.md)
で見た投機実行（分岐結果を待たず先読み実行する高速化）を悪用する、ソフトウェアだけの非侵襲的攻撃。

| | Meltdown (CVE-2017-5754) | Spectre (CVE-2017-5753/5715) |
|---|---|---|
| 悪用する仕組み | アウト・オブ・オーダー実行（実行可能になった順に処理） | 分岐予測器を「毒する」 |
| 何が起きる | 権限チェック前の一瞬に禁止領域を投機的に読む | 被害者に禁止領域を投機的に読ませる |
| 崩れる境界 | OS / ユーザー（主に Intel） | プロセス間（Intel/AMD/ARM ほぼ全て） |

どちらも「投機実行の結果はレジスタ・メモリに残らないが、**触れたキャッシュの状態だけは残る**」性質を [Flush+Reload](../01_prerequisites/03_hardware-digital-logic/03_hdl-and-architecture/03_memory-hierarchy-and-codesign.md) で読み出す。

```mermaid
flowchart LR
    A["投機実行で禁止領域を読む"] --> B["結果は破棄（なかったこと）"]
    B --> C["触れたキャッシュの状態だけ残る"]
    C --> D["キャッシュタイミングで 1 バイトずつ復元"]
```

攻撃の最終段の「キャッシュタイミングでの読み出し」は次の[04](./04_side-channels/README.md)で扱う。

## この2種類の攻撃の対比

| | フォールト注入 | Spectre/Meltdown |
|---|---|---|
| 攻撃者の行為 | 計算を**能動的に**妨害する | 実行を**受動的に**観測する |
| 必要な物理アクセス | 半侵襲的（電圧/レーザー等） | 非侵襲的（ソフトウェアのみ） |
| 崩れる保証 | 正しい計算結果 | プロセス/権限の分離 |

## 演習（解答つき）

1. RSA-CRTフォールト攻撃で、なぜ `mod q` 側ではなく `mod p` 側だけにフォールトを
   注入すると `q` が求まるのか一言で述べよ。
2. Meltdown と Spectre の主な違いを一言で述べよ。
3. 半侵襲的攻撃が「安価で再現しやすい」とされる理由を非侵襲的・侵襲的と対比して述べよ。
4. 出荷済み製品の基板に UART のテストポイントが残っていた。上記の段階1〜5のどこに効く
   問題か。設計段階で取りうる対策を2つ挙げよ。

<details><summary>解答</summary>

1. フォールトが `mod p` 側の計算だけを乱すため、`s` と `s'` は `mod q` では一致するが
   `mod p` では一致しない。差 `s-s'` は `q` の倍数だが `p` の倍数ではなくなるため、
   `gcd(s-s', n)` を取ると `p` は約分されず `q` だけが残る。
2. Meltdown はアウト・オブ・オーダー実行を悪用してOS/ユーザー間の権限境界を崩す
   （主にIntel）。Spectre は分岐予測器を毒してプロセス間の分離を崩す
   （Intel/AMD/ARMほぼ全て）。
3. 非侵襲的攻撃よりチップ内部の状態に近づけるため精度が高く効果的だが、
   侵襲的攻撃のような内部配線への直接接触は必要ないため、機材コストと専門性の要求が
   侵襲的攻撃よりずっと低く、再現・量産がしやすい。
4. **段階3（インタフェース特定）**。攻撃者はロジックアナライザで信号を観測するだけで
   デバッグ経路を見つけられ、そこから段階4のファームウェア吸い出しへ進める。
   対策例: ①出荷時にデバッグ機能をヒューズ等で恒久的に無効化する
   ②テストポイントを外層に露出させず内層に埋める。
   加えて段階4を止める手段（セキュアブート・フラッシュの暗号化）を併用すると、
   仮に経路を見つけられても得られる情報を限定できる。

</details>
