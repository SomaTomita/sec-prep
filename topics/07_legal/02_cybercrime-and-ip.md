# 02. サイバー犯罪と知的財産

> 対応科目: H0Q25A ｜ 前: [01 法務の全体地図](./01_legal-landscape.md) ｜ 層: 基礎(Layer 1)

[01](./01_legal-landscape.md) で見た法令群は「事業者が何をすべきか」を定める規制法だった。
本ファイルは視点を変え、**攻撃者を訴追する刑事法の枠組み**と、
**ソフトウェアという成果物をどう法的に保護するか**という知財の話を扱う。
どちらもサイバーセキュリティ実務に隣接するが、性質の異なる法分野。

---

## サイバー犯罪の国際的な枠組み

### ブダペスト条約（サイバー犯罪に関する条約）

```
Council of Europe（欧州評議会、EUとは別組織）が起草
2001年11月8日 閣僚委員会で採択、2001年11月23日ブダペストで署名開放
サイバー犯罪に関する初の国際条約——加盟国の法制度を調和させ、
捜査手法（ネットワーク捜索・通信傍受）を整備し、
国際協力の枠組み（証拠保全の要請等）を確立
```

日本・米国・カナダ等、欧州評議会加盟国以外もオブザーバーとして起草に参加し、
現在では欧州以外の国も多数締結している——「地域条約」ではなく
事実上のグローバルスタンダードとして機能している点が特徴。

### EU域内の実装: 情報システム攻撃指令

```
Directive 2013/40/EU（情報システムに対する攻撃に関する指令）
2013年8月12日成立
EU加盟国限定で、ブダペスト条約より対象が狭い
（捜査手続きの規定は持たず、最低限の量刑水準の統一と、
  加盟国間の24時間365日の緊急連絡網の整備を義務付け）
```

ブダペスト条約が「国際協力の基盤」、2013/40/EU指令が「EU域内での量刑・
緊急対応体制の統一」という役割分担になっている。

## 越境捜査の壁: 管轄権と電子証拠

サイバー犯罪捜査の最大の実務上の壁は、**証拠（電子データ）がどこにあるか**が
攻撃者の所在地と一致しないこと。クラウド事業者のサーバーが別の国にあれば、
捜査機関は他国の司法協力（相互法的支援条約=MLAT等）を経由する必要があり、
これが従来は数か月〜数年かかっていた。

### EUのe-evidence規則

```
Regulation (EU) 2023/1543 + Directive (EU) 2023/1544（e-evidenceパッケージ）
2026年8月18日から全加盟国（デンマークを除く）で適用開始
```

この枠組みは、ある加盟国の捜査機関が**別の加盟国に拠点を置くサービス事業者に
対して直接**電子証拠の開示・保全を要求できる仕組みを作る（提供国の当局の関与を
原則不要にする）。

```
European Production Order:  加入者情報・アクセスデータ・通信データ・内容データの
                             開示を事業者に直接要求
European Preservation Order: 将来の開示要求に備えてデータの保全を事業者に要求
```

EU域外に本拠を置く事業者も、EU域内で事業を行う限り**法定代理人の指定**が
義務付けられる（Directive 2023/1544）——GDPRの域外適用と同じ発想が
刑事手続きにも及んでいる。

## ソフトウェアの知的財産: 著作権と特許

| | 著作権 (Copyright) | 特許 (Patent) |
|---|---|---|
| 保護対象 | コードの**表現**（ソースコードそのもの） | **発明**（アイデア・アルゴリズムの実装方法） |
| 発生要件 | 創作した時点で自動的に発生（登録不要） | 出願・審査・登録が必要 |
| ソフトウェアでの扱い | 明確に保護対象（プログラムは「文学的著作物」に類する扱い） | EUでは限定的（下記） |

### 欧州特許条約(EPC)第52条(2)(3): ソフトウェア特許の制限

```
第52条(2): 「コンピュータプログラム」は特許の対象となる「発明」に含まれない
第52条(3): ただし、この除外は「コンピュータプログラムそれ自体(as such)」を
           対象とする限りにおいて適用される
```

つまり除外は絶対的ではない——**技術的性格(technical character)**を持つ
発明（例: プログラムがハードウェアの制御方法に技術的な貢献をする場合）は
「それ自体」の除外に当たらず特許を取得しうる、というのが欧州特許庁(EPO)の
運用。「アイデア自体」と「技術的課題を解決する実装」の境界線をどう引くかが
判例の蓄積で決まっていく分野で、米国の特許制度（ソフトウェア特許により
寛容）とは運用が異なる。

---

## OSSライセンス: パーミッシブ vs コピーレフト

著作権が「自動的に発生する」からこそ、ソースコードを公開する側は
**ライセンス**で利用条件を明示する必要がある。

```
パーミッシブ (Permissive) 例: MIT, Apache 2.0, BSD
  再配布時の条件が緩い——改変版を非公開のプロプライエタリソフトとして
  再配布してもよい（著作権表示の保持等、最小限の条件のみ）

コピーレフト (Copyleft) 例: GPL, AGPL
  改変・派生物を配布する場合、同じライセンス（ソースコード公開義務含む）を
  引き継がせる——「自由なソフトウェアであり続けること」を法的に強制する仕組み
```

企業がOSSを製品に組み込む際、コピーレフトライセンスのコードを
プロプライエタリ製品に混入させると**自社コードの公開義務**が発生しうるため、
ライセンス監査（どのOSSがどのライセンスで使われているか）は
セキュアSDLCの一部としても実務上重要になる。

## 演習（解答つき）

1. ブダペスト条約とEU指令2013/40/EUの役割分担を一言で述べよ。
2. EUのe-evidence規則が「MLAT（相互法的支援条約）経由の捜査」と比べて
   何を変えるか述べよ。
3. 「特定のアルゴリズムのソースコード」と「そのアルゴリズムのアイデア」を
   それぞれ著作権・特許のどちらが保護しうるか、EPC第52条の枠組みで説明せよ。

<details><summary>解答</summary>

1. ブダペスト条約は欧州評議会が起草した国際条約で、捜査手続きの調和と
   国際協力の基盤を提供する（欧州域外にも適用が広がるグローバルな枠組み）。
   2013/40/EU指令はEU加盟国限定で、量刑の最低水準統一と24時間緊急連絡網の
   整備に特化した、より狭い実装。
2. 提供国の当局を経由する必要がなくなり、捜査機関が別の加盟国の
   サービス事業者に**直接**電子証拠の開示・保全を要求できるようになる——
   MLATで数か月〜数年かかっていた手続きを大幅に短縮する狙い。
3. ソースコードそのもの（表現）は著作権で自動的に保護される。アルゴリズムの
   アイデア自体はEPC第52条(2)により「コンピュータプログラムそれ自体」として
   特許から除外されるが、そのアルゴリズムが技術的課題を解決する
   技術的性格を持つ実装として具体化されていれば、第52条(3)の限定により
   特許の対象になりうる。

</details>
