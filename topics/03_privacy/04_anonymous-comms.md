# 04. 匿名通信（Mixネットワーク・オニオンルーティング・Tor）

> 前: [03 暗号的PET](./03_ppt-cryptographic.md) ｜ 次: [05 Web上のプライバシー](./05_web-privacy-tracking.md) ｜ 層: 基礎(Layer 1)

これまでは**データの中身**や**問い合わせ内容**を隠す技術だった。ここでは
「誰が誰と通信しているか」という**通信路のメタデータ**そのものを隠す。
[01](./01_privacy-concepts.md) で見た **非連結性・非観測性**を実際のネットワーク設計で
実現する試み。

---

## Mixネットワーク（David Chaum, 1981年）

```
アイデア: 複数の送信者からの暗号化メッセージを1つのサーバ（mix）にまとめて受け取り、
  順序をシャッフルしてから次へ転送する。1つの mix だけを見ても
  「どのメッセージがどの送信者から来たか」が分からなくなる
```

論文タイトルは *Untraceable Electronic Mail, Return Addresses, and Digital Pseudonyms*
（追跡不可能な電子メール）。公開鍵暗号で**多重に暗号化**（各 mix 用の層を持つ）し、
各 mix は自分宛ての1層だけ復号して次へ転送する——後の Tor・I2P の理論的土台になった。

**特性**: バッチ処理・シャッフルにより強い匿名性を狙えるが、メッセージを溜めてから
まとめて転送するため**遅延が大きい**。リアルタイム性が要らない電子メールには向くが、
ウェブ閲覧のような対話的通信には不向き。

## オニオンルーティングと Tor

低遅延の匿名通信を目指し、Mixネットワークのアイデアを**リアルタイム回線**に応用した
のがオニオンルーティング。Tor（Dingledine, Mathewson, Syverson, 2004年、USENIX Security）が
その代表的な実装。

### 3ホップ回線（Guard・Middle・Exit）

```
クライアント → Guard（入口） → Middle（中継） → Exit（出口） → 宛先サーバ

各ホップとは ntor ハンドシェイク（Curve25519上のECDH、03_ecc.md参照）で個別に鍵を確立し、
その鍵で層状に暗号化（各ホップは自分宛ての1層だけをAES-128-CTRモードで復号して転送）
```

CTRモードでのデータ保護は [`../02_cryptography/02_symmetric-crypto.md`](../02_cryptography/02_symmetric-crypto.md)
で見た仕組みそのもの——ここでは各ホップ間の通信路の暗号化に使われている。

**核心の設計原則**: **どの1つの中継ノードも「送信元と宛先の両方」を同時に知らない。**

```
Guard: クライアントのIPは知るが、最終的な宛先は知らない
Exit:  最終的な宛先とその内容は知るが、クライアントのIPは知らない
Middle: 両方とも知らず、ただ暗号化されたセルを中継するだけ
```

---

## Tor の限界：トラフィック相関攻撃

Tor の暗号（ECDH・AES）自体は破られていない。それでも匿名性が崩れるケースがある。

```
トラフィック相関攻撃: Guard側の通信とExit側の通信の「タイミング」「データ量」パターンを
  両方観測できる攻撃者が、統計的にそれらを突き合わせることで
  送信元と宛先を結びつけてしまう
```

これが成立するには **Guard と Exit の両方を観測できる立場**（国家レベルの監視者、
悪意ある中継ノード運用者、多くの中継を保持する自律システム(AS)等）が必要。

**教訓（コース全体を貫くテーマの再登場）**: 「暗号化アルゴリズムが正しく実装されている」
ことと「システム全体として匿名性が守られる」ことは別問題。RSAパディング
（[`../02_cryptography/03_public-key-crypto/01_rsa/04_padding-and-attacks.md`](../02_cryptography/03_public-key-crypto/01_rsa/04_padding-and-attacks.md)）や
ECDSAのnonce再利用（[`../02_cryptography/03_public-key-crypto/04_digital-signatures.md`](../02_cryptography/03_public-key-crypto/04_digital-signatures.md)）が
「実装レベル」の教訓だったのに対し、トラフィック相関は
**「メタデータ・統計パターンレベル」**で同じ教訓が再登場したもの。

**設計上の前提**: Tor はそもそも「あらゆる場所の通信を観測できるグローバルな受動的
観測者」に対する防御は目標としていない——現実的な単一の観測者・限定的な攻撃者を
想定した設計であることが公式に明言されている。

## まとめ表

| 方式 | 匿名性の強さ | 遅延 | 主な用途 |
|---|---|---|---|
| Mixネットワーク | 強い（バッチ・シャッフル） | 大きい | 電子メール等の非対話的通信 |
| オニオンルーティング（Tor） | 中程度（相関攻撃に弱い） | 小さい（リアルタイム） | ウェブ閲覧等の対話的通信 |

## 演習（解答つき）

1. Mixネットワークがウェブブラウジングに向かない理由を一言で述べよ。
2. Tor の3ホップ設計で、Middle（中継）ノードが単独で送信元も宛先も知り得ない理由を述べよ。
3. トラフィック相関攻撃がTorの「暗号の欠陥」ではないと言える理由を述べよ。

<details><summary>解答</summary>

1. メッセージをバッチにまとめてシャッフルしてから転送するため遅延が大きく、
   即座の応答が必要な対話的なウェブ閲覧には適さない。
2. Middleノードは自分の前後のホップ（Guardの次・Exitの前）としか通信せず、
   層状暗号化により自分より外側の層（元の送信者情報や最終宛先）を復号する鍵を持たない。
3. 各ホップ間の暗号化（ECDHによる鍵確立・AES-CTRでの暗号化）自体は破られていない。
   相関攻撃は暗号文の中身を解読するのではなく、通信の**タイミングやデータ量という
   メタデータの統計的パターン**を外部から観測・突き合わせるだけで成立するため、
   暗号アルゴリズムの正しさとは独立した脅威。

</details>
