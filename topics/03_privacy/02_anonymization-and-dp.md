# 02. 匿名化と差分プライバシー

> 対応科目: H00Y2A, H09L2A ｜ 前: [01 プライバシーの基本概念](./01_privacy-concepts.md) ｜ 次: [03 暗号的PET](./03_ppt-cryptographic.md) ｜ 層: 基礎(Layer 1)

[01](./01_privacy-concepts.md) の「匿名性集合」を**実データ**で作る古典的手法（k-匿名化とその

（差分プライバシー）に進む。

## 準識別子と k-匿名化

```
準識別子 (quasi-identifier): 単体では個人を特定できないが、組み合わせると特定できる属性
  例: 郵便番号・性別・生年月日

k-匿名化 (Samarati & Sweeney, 1990年代後半; Sweeney, 2002年):
  公開データの各レコードが、準識別子に関して少なくとも他 k-1 件のレコードと
  区別できないようにする（一般化・抑制で属性値を粗くする）
```

Sweeney の有名な発見: 米国人口の **87%**（2億4800万人中2億1600万人）は
`{5桁の郵便番号, 性別, 生年月日}` の組だけで一意に特定できる——
「匿名化された」データでも準識別子の組み合わせだけで個人が浮かび上がる典型例。

### 小さな例：一般化による k=2 の達成

| 元データ（年齢, 郵便番号） | k=2 に一般化後 |
|---|---|
| (23, 12345) | (20-29, 1234*) |
| (27, 12349) | (20-29, 1234*) |
| (45, 54321) | (40-49, 5432*) |
| (48, 54329) | (40-49, 5432*) |

各グループが2件ずつになるよう年齢を区間化・郵便番号を末尾抑制。
これで「準識別子の組」からは各レコードが2件中のどちらか区別できない。

## k-匿名化の弱点：等質性攻撃と背景知識攻撃

k-匿名化は**準識別子**しか見ていないため、次の攻撃に無力（Machanavajjhala et al., 2007年）:

```
等質性攻撃 (homogeneity attack):
  あるグループの k 件全員が同じ「機微な属性値」（例: 同じ病名）を持っていれば、
  k-匿名化を満たしていても機微な値がそのまま漏れる

背景知識攻撃 (background knowledge attack):
  「日本人は心臓病の発症率が低い」等の外部知識と組み合わせると、
  グループ内で機微な値の候補を絞り込める
```

### l-多様性（Machanavajjhala et al., 2007年）

```
各グループ内で、機微な属性値の同じ値を持つレコードが全体の 1/l 以下になるよう制約する
```

等質性攻撃は防げるが、機微な値の**分布の偏り**（例: グループ内の値が多様でも
大半が「軽症」でごく少数が「重症」）までは守れない。

### t-近接性（Li et al., 2007年）

```
各グループ内の機微な属性値の分布が、データセット全体の分布と
「近い」（距離が閾値 t 以下）ことを要求する
```

l-多様性が見落とす**分布の類似性・歪度**まで踏み込んで制約する、より強い基準。

## それでも破られる：実際に起きた再識別事件

構文的な匿名化（k-匿名化系列）は、攻撃者が持つ**外部データとの突き合わせ**に
原理的に弱い。

- **AOL検索ログ流出（2006年）**: AOLが650万人以上のユーザーIDを乱数に置き換えて
  2000万件の検索クエリを公開。しかしクエリの内容（自分の名前・住所・趣味などを
  検索する癖）から、New York Times が「ユーザー#4417749」を
  ジョージア州在住62歳の Thelma Arnold と特定。AOLのCTOが引責辞任した。
- **Netflix Prize データセットの再識別（Narayanan & Shmatikov, 2008年）**:
  Netflixが匿名化して公開した50万人分の映画評価データを、IMDbの**公開レビュー**と
  突き合わせるだけで多くの利用者を再識別できることを実証。

**教訓**: 「準識別子を隠す」という発想そのものが、攻撃者がどんな外部知識を持つか
事前に想定しきれないという構造的な限界を持つ。

## 差分プライバシー（Differential Privacy, Dwork et al., 2006年）

k-匿名化系列とは根本的に異なる、**数学的に証明可能な**プライバシー保証。

```
ランダム化アルゴリズム M が ε-差分プライバシーを満たすとは:
  1件だけ異なる任意の2つのデータセット D, D'（隣接データセット）と
  任意の出力集合 S について
      Pr[M(D)∈S] ≤ e^ε · Pr[M(D')∈S]
  が成り立つこと
```

意味: **「自分のデータが含まれていようといまいと、出力の分布はほとんど変わらない」**
という保証を、攻撃者がどんな背景知識を持っていても成り立つ形で数学的に証明する。
`ε`（プライバシー予算）が小さいほど保証は強く、その代わりノイズが増えて有用性が下がる
——プライバシーと有用性のトレードオフを明示的なパラメータで制御できる。

### ラプラスメカニズム

数値クエリ（例: 「病気Xの患者は何人？」）に対する最もシンプルな実現方法。

```
真の答え f(D) に、スケール Δf/ε のラプラス分布からサンプリングしたノイズを加えて出力する
Δf（感度）: 1件のレコードの増減で f の値が最大どれだけ変わりうるか
```

例えば「人数を数える」クエリなら1人の増減で結果は高々1しか変わらないので `Δf=1`。
`ε` を小さくする（プライバシーを強くする）ほど、加えるノイズのスケールが大きくなる。

### 予算の合成

複数回クエリに答えるたびにプライバシー漏洩が積み重なる（`ε`の合計が実効的な保証になる）。
そのため実運用では「予算 `ε` をどう配分するか」の設計が重要になる。

---

## まとめ表

| 手法 | 何を守るか | 弱点 |
|---|---|---|
| k-匿名化 | 準識別子からの再識別 | 等質性攻撃・背景知識攻撃 |
| l-多様性 | 機微属性の偏り | 分布の類似性攻撃までは防げない |
| t-近接性 | 機微属性の分布の歪み | 実装・パラメータ選定が複雑 |
| 差分プライバシー | 個人の存在有無そのもの | ノイズによる有用性の低下、予算管理の難しさ |

## 演習（解答つき）

1. k-匿名化を満たすデータで等質性攻撃が成立する条件を一言で述べよ。
2. AOL事件でk-匿名化系列の手法（IDの置き換えのみ）が失敗した根本原因を述べよ。
3. `ε` を大きくすると差分プライバシーの保証と有用性はそれぞれどうなるか。

<details><summary>解答</summary>

1. 準識別子で作られたグループ（k件）内の全レコードが、同じ機微な属性値を持つ場合。
   グループ内でどのレコードが本人かは分からなくても、機微な値自体は一意に定まってしまう。
2. IDを乱数に置き換えるだけでは**準識別子に相当する情報（検索クエリの内容自体）**が
   平文のまま残っており、外部の公開情報（本人が検索した固有名詞等）と突き合わせれば
   再識別できてしまう。k-匿名化のような体系的な一般化を全く行っていなかった。
3. `ε` を大きくすると、隣接データセット間の出力分布の許容される差が大きくなるため
   **プライバシー保証は弱くなる**が、必要なノイズが減るため**有用性（結果の精度）は上がる**。

</details>
