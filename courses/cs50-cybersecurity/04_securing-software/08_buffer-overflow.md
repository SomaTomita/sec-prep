# 08. バッファオーバーフロー

> 親: [README](./README.md) ｜ 前: [CSRF](./07_csrf.md) ｜ 次: [供給網と脆弱性カタログ](./09_supply-chain-and-vulnerability-catalogs.md) ｜ 出典: 講義4 (05:57:55–06:10:57)

**この1ページで分かること**

- スタック上でバッファと戻りアドレスは隣接する。溢れさせれば戻り先を書き換えられる
- 攻撃コードを置き、戻りアドレスをその位置に向けると任意コード実行が成立する
- リバースエンジニアリングは中立の技術。攻撃者は脆弱性探しに、防御側はマルウェア解析に使う

最後に扱うのは、自分の端末で動く**ネイティブなソフトウェア**への攻撃である。「入力が命令として解釈される」の 4 度目にあたる。

---

## プログラム実行時のメモリ

プログラムを起動するとメモリに読み込まれる。メモリは大きな長方形の領域で、用途ごとに場所が決まっている。物理法則ではなく人間が昔決めた**取り決め**である。

```
 ┌──────────────────────────────┐
 │  機械語(machine code)         │  プログラムそのもの。0 と 1 の命令列
 │  ...                          │
 ├──────────────────────────────┤
 │                               │
 │  (空き)                       │
 │                               │
 ├──────────────────────────────┤
 │  スタック(stack)              │  実行中に必要になった分だけ積む
 │   ├ フレーム3                 │  ↑ 必要になるたび積み増す
 │   ├ フレーム2                 │
 │   └ フレーム1                 │  ← ここから使い始める
 └──────────────────────────────┘
```

| 領域 | 中身 |
|---|---|
| **機械語** | プログラムの命令そのもの。0 と 1 の並び |
| **スタック** | 実行中に必要なメモリを積み重ねて使う領域 |

スタックは食堂のトレイのように**積み重ねて**使う。関数を呼ぶたびに 1 段（フレーム）積み、終われば取り除く。入力の受け取りやゲームの面の読み込みで追加要求し、不要になれば手放す。

## 戻りアドレス

プログラムは機械語の中を飛び回る。メニューの「印刷」を選べば印刷の処理へ跳び、終われば元の作業に戻る。跳ぶ前に**「終わったらここに戻れ」というメモ**が要る。これが**戻りアドレス**（return address）である。

検索機能を呼んだときのスタック。

```
呼び出し直後                      入力を受け取った後
 ┌────────────────┐               ┌────────────────┐
 │                │               │ "cats"         │ ← 入力用に確保した領域
 │                │               ├────────────────┤
 ├────────────────┤               ├────────────────┤
 │ 戻りアドレス   │ ←このメモ     │ 戻りアドレス   │
 └────────────────┘               └────────────────┘
```

`cats` は確保した領域に収まっている。検索が終わればフレームは取り除かれ、戻りアドレスに従って元の位置へ戻る。正常な動作である。

## 溢れさせる

問題は、**プログラマが入力の長さを見積もって領域を確保している**ことにある。見積もりを超えた分は**隣接する領域に書き込まれる**。

```
 想定内                            想定を超える入力
 ┌────────────────┐               ┌────────────────┐
 │ "cats"         │               │ 攻撃コード     │
 │ (空き)         │               │ 0101110100...  │ ← バッファを溢れた分が
 ├────────────────┤               ├────────────────┤    隣の領域を上書き
 │ 戻りアドレス   │               │ ★上書きされた  │
 └────────────────┘               └────────────────┘
```

バッファ（確保した入力用の領域）と戻りアドレスは同じフレームの中で隣り合っている。だから**バッファを溢れさせれば戻りアドレスに届く**。

これだけならプログラムが異常終了するだけだ。攻撃者はもう一歩進める。

1. 入力の前半に、実行させたい**攻撃コード**（命令を表す 0 と 1 の並び）を置く
2. 入力の末尾が、ちょうど戻りアドレスの位置に重なるよう長さを調整する
3. そこに書く値を、**攻撃コードを置いた位置のアドレス**にする

```
 ┌────────────────┐
 │ 攻撃コード     │ ◀──┐  ③ ここへ戻れ、と指させる
 │ 0101110100...  │    │
 ├────────────────┤    │
 │ 攻撃コードの   │────┘  ② 戻りアドレスを攻撃コードの位置で上書き
 │ アドレス       │
 └────────────────┘
```

関数が終わると CPU は戻りアドレスを読んでそこへ跳ぶ。跳んだ先には攻撃者のコードがある。同梱されていたはずのない命令が、そのプログラムの一部として実行される。

一度で成功することは稀で、長さやアドレスを変えながらの試行錯誤になる。しかし成立すれば結果は決定的である。

## 任意コード実行

| 用語 | 意味 |
|---|---|
| **任意コード実行**（arbitrary code execution） | 攻撃者の任意の命令が実行される |
| **遠隔コード実行**（remote code execution） | 同じ入力をネットワーク越しに送り込める場合 |
| **cracking** | シリアル番号の確認処理を飛ばす書き換え。同技術の軽い応用 |

できることは[コマンドインジェクション](./05_command-injection.md)と同じく、**そのプログラムを動かしている利用者の権限でできること全部**である。ファイルの削除、データの送信、スパムの送出、常駐化。任意のコードが入り込んだ時点で境界は無い。

---

## リバースエンジニアリング

配布されるソフトウェアは 0 と 1 の並びで、そのままでは中身が読めない。試行錯誤と解析でその 0 と 1 がどんな命令かを復元することを、**リバースエンジニアリング**（どう作られたかを逆向きに解き明かすこと）と呼ぶ。

| 立場 | 用途 |
|---|---|
| 攻撃側 | 脆弱性の在り処を探す。シリアル確認の回避（cracking） |
| 防御側 | **マルウェア解析** — 検体の挙動を突き止め、アンチウイルスの検知規則に反映する |

技術は中立で、目的が向きを決める。なお、プログラマ向け Q&A サイト stackoverflow.com の名前は、まさにこのスタックが溢れる現象に由来している。

## 問題

**Q1.** プログラム実行時のメモリで、機械語とスタックはそれぞれ何を保持しているか。戻りアドレスとは何か。

<details><summary>解答</summary>

- 機械語: プログラムそのものの命令列（0 と 1）。実行中に CPU がここを読んで動く。
- スタック: 実行中に必要になったメモリを積み重ねて使う領域。関数を呼ぶたびにフレームを積み、終われば取り除く。
- 戻りアドレス: ある処理へ跳ぶ前に残す「終わったらこの位置へ戻れ」というメモ。機械語のどこへ戻るかを指す値。

</details>

**Q2.** バッファオーバーフローが戻りアドレスに届いてしまう理由を述べよ。

<details><summary>解答</summary>

プログラマは入力の長さを見積もってバッファを確保しており、その見積もりを超える入力は確保した領域に収まらず隣接する領域へ書き込まれる。バッファと戻りアドレスは同じフレームの中で隣り合っているため、溢れた分が戻りアドレスを上書きする。

</details>

**Q3.** 単に戻りアドレスを壊すと異常終了するだけである。攻撃者が任意コード実行まで持っていくために行う 3 段階を述べよ。

<details><summary>解答</summary>

1. 入力の前半に、実行させたい攻撃コード（命令を表す 0 と 1 の並び）を置く。
2. 入力の長さを調整し、末尾がちょうど戻りアドレスの位置に重なるようにする。
3. 戻りアドレスの位置に書く値を、攻撃コードを置いた位置のアドレスにする。

関数終了時に CPU がその値を読んで跳ぶと、攻撃者のコードが実行される。実際には長さとアドレスを変えながらの試行錯誤を要する。

</details>

**Q4.** リバースエンジニアリングが攻撃と防御の両方に使われる例をそれぞれ挙げよ。

<details><summary>解答</summary>

- 攻撃側: 配布されたソフトウェアの 0 と 1 を解析して脆弱性の在り処を探す。またシリアル番号の確認処理を特定して回避する（cracking）。
- 防御側: マルウェア解析。感染した検体を解析して挙動を突き止め、アンチウイルスの検知規則に反映する。

技術自体は中立で、目的によって向きが決まる。

</details>
