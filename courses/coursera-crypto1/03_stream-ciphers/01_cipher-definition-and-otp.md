# 01. 暗号の定義と OTP

> 親: [README](./README.md) ｜ 前: [README](./README.md) ｜ 次: [PRG とストリーム暗号](./02_prg-and-stream-ciphers.md) ｜ 出典: Crypto I ビデオ1 (1:17:16–1:35:40)

「暗号とは何か」を式で固定するところから始める。素朴に作った暗号がなぜ危ういのか、そして OTP(ワンタイムパッド)が理論上は「破れない」と言える意味(Shannon の完全秘匿)と、その代償を見る。

---

## 暗号の正式な定義

暗号 (cipher) とは、鍵空間 `K`・平文空間 `M`・暗号文空間 `C` の上で定義される、**効率的アルゴリズムの対** `(E, D)` である:

```
E : K × M → C        （暗号化。乱択でよい）
D : K × C → M        （復号。決定的でよい）
```

満たすべき唯一の性質が**正当性 (correctness)**:

```
∀ m ∈ M, ∀ k ∈ K :   D(k, E(k, m)) = m
```

つまり「正しい鍵で暗号化したものは、同じ鍵で必ず元に戻る」。E は乱数を使ってよい(同じ `m` でも暗号文が毎回変わりうる)が、D は同じ `(k,c)` に必ず同じ `m` を返す決定的関数でよい。

---

## OTP(Vernam 暗号)

最も単純な暗号。`M = C = K = {0,1}^n`(鍵・平文・暗号文がすべて同じ長さのビット列):

```
鍵生成 :  k ←$ {0,1}^n   （一様ランダムな n ビット)
暗号化 :  c = E(k, m) = k ⊕ m
復号   :  m = D(k, c) = k ⊕ c
```

正当性は XOR の性質から即座に従う: `D(k, E(k,m)) = k ⊕ (k ⊕ m) = (k ⊕ k) ⊕ m = 0 ⊕ m = m`。

長所は速さ(XOR だけ)。短所は決定的で、**鍵が平文と同じ長さ**であること。鍵を安全に配送できるなら、その配送路で平文を送れてしまう(鍵配送問題)。さらに `(m, c)` の対が 1 組でも漏れると `k = m ⊕ c` で鍵が丸ごと復元される。

### 動かして確かめる

`c = k ⊕ m` を 1 ビットずつ計算し、そのまま `m = k ⊕ c` まで進む。鍵を変えても平文を変えても、`m` は必ず元に戻る(=正当性)。

## Shannon の完全秘匿 (perfect secrecy)

暗号文だけを見た攻撃者が、平文について**何も**学べないことを厳密にした定義。鍵 `k` を一様ランダムとしたとき:

```
∀ 同じ長さの m0, m1 ∈ M, ∀ c ∈ C :
    Pr[ E(k, m0) = c ] = Pr[ E(k, m1) = c ]
```

意味は「どの暗号文 `c` を観測しても、それが `m0` を暗号化したものか `m1` を暗号化したものか区別できない」。つまり**暗号文単独攻撃 (ciphertext-only attack) が原理的に不可能**。ただし守るのは「暗号文だけから平文を推測する」攻撃であって、改竄や鍵の使い回しは対象外である点に注意(次ファイル以降)。

---

## OTP は完全秘匿である

任意の平文 `m` と暗号文 `c` について、「`E(k,m) = c` を成立させる鍵 `k` が何個あるか」を数える。OTP では `k ⊕ m = c ⟺ k = m ⊕ c` なので、条件を満たす鍵は **ちょうど 1 個**(`k = m ⊕ c`)。鍵は一様なので:

```
Pr[ E(k, m) = c ] = (条件を満たす鍵の数) / |K| = 1 / 2^n
```

この値は `m` に依存しない定数。ゆえに `m0, m1` のどちらでも確率は等しく、完全秘匿の定義を満たす。

---

## Shannon の悪い知らせ: |K| ≥ |M|

完全秘匿には必ず「鍵空間が平文空間以上」という代償がつく:

```
完全秘匿 ⇒ |K| ≥ |M|
```

直感: 各暗号文 `c` は、どの平文からも到達可能でなければならない(そうでないと `c` を見た時点で一部の平文を除外でき、区別がついてしまう)。1 つの `c` に対し平文ごとに別の鍵が要るので、鍵は平文と同じだけ必要になる。OTP は `|K| = |M| = 2^n` で等号を達成する**最適な**完全秘匿暗号だが、鍵がメッセージと同長という時点で大量通信には非現実的。次ファイルでは「完全秘匿を諦め、計算量的な安全性に切り替える」道を辿る。

---

## 問題

**Q1.** `n = 4`、`m = 1011`、`k = 0110` のとき OTP 暗号文 `c` を求めよ。

<details><summary>解答</summary>

`c = k ⊕ m = 0110 ⊕ 1011 = 1101`。

</details>

**Q2.** ある OTP 通信を盗聴し、平文 `m = 0101` とその暗号文 `c = 1100` の対を入手した。鍵 `k` を復元せよ。

<details><summary>解答</summary>

`k = m ⊕ c = 0101 ⊕ 1100 = 1001`。1 組の既知平文で鍵が丸ごと漏れる。

</details>

**Q3.** OTP は完全秘匿だが、それでも防げない攻撃を 2 つ挙げよ。

<details><summary>解答</summary>

(1) **改竄**: 攻撃者が `c` を `c ⊕ p` に書き換えると復号結果が `m ⊕ p` になり、狙った位置を反転できる(可鍛性)。(2) **鍵の使い回し**: 同じ `k` で 2 つの平文を暗号化すると `c1 ⊕ c2 = m1 ⊕ m2` となり秘匿が崩れる(two-time pad)。完全秘匿はあくまで「暗号文単独から平文を推測する攻撃」に対する保証。

</details>

**Q4.** 「完全秘匿 ⇒ |K| ≥ |M|」は実務上どんな帰結をもたらすか。

<details><summary>解答</summary>

鍵を平文と同じ長さだけ用意し、安全に配送しなければならない。長いメッセージほど長い鍵が要り、鍵配送問題が解決できない。だから実務では完全秘匿を諦め、短い鍵で計算量的に安全なストリーム暗号へ移行する。

</details>
