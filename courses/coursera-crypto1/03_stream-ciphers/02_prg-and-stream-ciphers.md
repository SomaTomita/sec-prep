# 02. PRG とストリーム暗号

> 親: [README](./README.md) ｜ 前: [暗号の定義と OTP](./01_cipher-definition-and-otp.md) ｜ 次: [OTP への攻撃](./03_attacks-on-otp.md) ｜ 出典: Crypto I ビデオ1 (1:35:40–1:55:24)

OTP の弱点は「鍵が平文と同じ長さ」だった。短い鍵から長い鍵ストリームを**擬似的に**作れば実用化できる。これがストリーム暗号。ただし完全秘匿は失われ、安全性は擬似ランダム生成器(PRG)の質にすべてかかる。

---

## PRG とストリーム暗号

**PRG (pseudorandom generator)** とは、短いシード(=鍵)を長いビット列に伸ばす**決定的**関数:

```
G : {0,1}^s → {0,1}^n       （n ≫ s。決定的）
```

ストリーム暗号は OTP の一様乱数鍵を `G(k)` に差し替えたもの:

```
暗号化 :  c = m ⊕ G(k)
復号   :  m = c ⊕ G(k)
```

鍵は `s` ビットだけで済む。ただし鍵空間 `2^s` は平文空間 `2^n` より小さいので、Shannon の定理(`|K| ≥ |M|`)により**完全秘匿は不可能**。安全性は「`G(k)` が本物の乱数と見分けられないか」という PRG の性質だけに依存する。

---

## 予測不可能性 (unpredictability)

PRG に最低限求めたい性質。「ストリームの一部を見ても、次のビットが当てられない」こと。逆に**予測可能**とは、ある位置 `i` について次が成り立つこと:

```
先頭 i ビット G(k)[1..i] を入力に、i+1 ビット目を
    確率 1/2 + ε  (ε は無視できない=non-negligible)
で当てる効率的アルゴリズム A が存在する
```

予測可能な PRG をストリーム暗号に使うと危険。攻撃者が平文の接頭辞を知っていれば(例: メールが必ず `From:` で始まる)、その部分の鍵ストリームを `k[i] = c[i] ⊕ m[i]` で復元でき、予測器で残りのストリームを次々に伸ばし、平文全体を復号できてしまう。

---

## 反例と危険な PRG

**反例(予測可能な PRG)**: 出力の全ビット XOR が常に 1 になるよう設計された `G`。攻撃者は先頭 `n-1` ビットを見て、その XOR を取り 1 と合わせれば最後の 1 ビットを確率 1 で当てられる。統計的にランダムに見えても予測可能。

**実務で使ってはいけない PRG**:

- **線形合同法 (LCG)**: `r ← a·r + b mod p` を回して出力するもの。出力を少し観測すると連立方程式で内部状態 `(a, b, r)` が解け、以後を完全予測できる。
- **glibc の `random()`**: 統計的な質は良いが暗号学的には予測可能。

これらは分布が一様に近くても**予測可能**なので暗号には不適。実例として **Kerberos v4** が弱い乱数源を使い、セッション鍵が予測されて破られた。

---

## negligible と non-negligible

「ε は無視できるほど小さいか」を測る語彙。実務では安全パラメータ `λ` に対する関数として扱う。

- **厳密版**: `ε(λ)` が negligible ⟺ どんな多項式 `p` に対しても、十分大きい `λ` で `ε(λ) < 1/p(λ)`。多項式より速く 0 に潰れる関数。
- **実務スカラー版(直感)**: `ε < 1/2^80` なら実質ゼロとみなす(無視可能)。`ε ≥ 1/2^30` は攻撃が現実的に成立するので無視できない。

```
例:  2^(-λ)      → negligible (指数的に潰れる)
     λ^(-1000)   → non-negligible (多項式なので潰れ方が遅い)
     1/1000      → 定数なので当然 non-negligible
```

---

## 問題

**Q1.** 「全ビットの XOR が常に 1」の PRG に対する予測器を、次ビット予測の枠組みで 1 行で述べよ。

<details><summary>解答</summary>

最後のビットを予測する `A`: 先頭 `n-1` ビットの XOR を計算し、それを 1 と合わせる値(= 先頭 XOR の反転)を出力する。常に的中するので成功確率 1、`ε = 1/2`。

</details>

**Q2.** 攻撃者はメールが `From:` で始まると知っている。ストリーム暗号の暗号文 `c` からこの接頭辞ぶんの鍵ストリームをどう得るか。

<details><summary>解答</summary>

平文接頭辞 `m[1..t] = "From:"` は既知。`G(k)[i] = c[i] ⊕ m[i]`(i = 1..t)で先頭 `t` バイトの鍵ストリームが判明する。PRG が予測可能ならここから残りを伸ばし、`c` 全体を復号できる。

</details>

**Q3.** 次の `ε(λ)` は negligible か non-negligible か。(a) `2^(-λ)` (b) `1/λ^5` (c) `λ^10 · 2^(-λ)`

<details><summary>解答</summary>

(a) negligible(指数的に潰れる)。(b) non-negligible(多項式の逆数)。(c) negligible(多項式を掛けても指数減衰が勝つ)。

</details>

**Q4.** 線形合同法や glibc の `random()` を暗号に使ってはいけない理由を一言で。

<details><summary>解答</summary>

統計的な質は良くても**予測可能**だから。出力を少し観測すれば内部状態を代数的に解け、以後の鍵ストリームが完全に再現され、平文が復号されてしまう(Kerberos v4 の失敗例)。

</details>
