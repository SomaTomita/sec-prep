# 01. コース概要と応用

> 親: [README](./README.md) ｜ 前: [README](./README.md) ｜ 次: [02 暗号にできること](./02_what-crypto-can-do.md) ｜ 出典: Crypto I ビデオ1 (0:00:00–0:10:24)

暗号（cryptography）は、敵対的な相手がいる環境でも通信やデータを守るための道具箱だ。まずこのコースが何を目指すのか、そして暗号が現実のどこで使われているのかを俯瞰する。

---

## コースの目標

Dan Boneh のこのコースは、次の4つを身につけることを狙う。

1. **暗号プリミティブの仕組み**を理解する（ブロック暗号・ハッシュ・鍵共有など）。
2. それらを**正しく使う**方法を知る（部品は正しくても組み合わせを誤ると壊れる）。
3. 構成の**安全性を推論する力**を養う（「なぜ安全と言えるか」を論証する）。
4. **安全でない構成を破る力**を持つ（攻撃の視点がないと安全性は評価できない）。

暗号は「使えばよい」道具ではなく、正しい使い方と限界を理解して初めて意味を持つ。

---

## 暗号は身の回りのどこにあるか

意識しなくても、暗号は日常のあらゆる通信・記録の裏側で動いている。

| 使われる場所 | 何を守るか |
|---|---|
| HTTPS（SSL/TLS） | Web ブラウザとサーバ間の通信 |
| Wi-Fi（WPA2 / 802.11i） | 無線 LAN の通信 |
| GSM・Bluetooth | 携帯電話・近距離無線の通信 |
| ディスク暗号化 | 保存されたファイル |
| DVD（CSS）／Blu-ray（AACS） | 映像コンテンツの保護 |

---

## 安全な通信の2部構成

インターネット上の安全な通信は、大きく2段階に分かれる。登場人物は送信者 **Alice**、受信者 **Bob**、そして通信を盗聴する**攻撃者（eavesdropper）**。

```
[第1部: ハンドシェイク]  公開鍵技術を使い、Alice と Bob が共有鍵 k を確立する
        Alice  <----- 鍵確立プロトコル ----->  Bob
                （盗聴者が見ていても k は漏れない）

[第2部: 通信]  確立した共有鍵 k で実際のデータをやり取りする
        Alice  --- c = E(k, m) --->  Bob  --- m = D(k, c)
```

**ディスク暗号化も同じ構造**として見ると分かりやすい。ファイルを暗号化して保存し、後で自分が復号するのは「**今日の Alice が明日の Alice へ送る通信**」と同型だ。相手が未来の自分になるだけで、鍵で守るという構造は変わらない。

---

## 対称暗号と Kerckhoffs の原則

第2部で使うのが**対称暗号**。暗号化 `E` と復号 `D` の2つのアルゴリズムと、共有鍵 `k` からなる。

```
暗号化:  c = E(k, m)     （m: 平文, c: 暗号文）
復号:    m = D(k, c)
```

Alice と Bob は同じ鍵 `k` を持つ。ここで設計上の大原則が **Kerckhoffs の原則**だ。

> 暗号アルゴリズム（`E`, `D`）は公開してよい。秘密にすべきなのは**鍵だけ**である。

このため**独自の秘密アルゴリズムを自作して使うべきではない**。理由は2つ。

- **査読の欠如**: 公開アルゴリズム（AES など）は世界中の専門家に解析され、弱点が洗い出されている。非公開の自作暗号はその検証を受けていない。
- **秘密は保てない**: 製品に組み込まれたアルゴリズムはリバースエンジニアリングで解析される。過去には、非公開だった暗号が解析後にただちに破られた事例が多数ある。

安全性をアルゴリズムの秘密に頼る設計（security through obscurity）は脆い。詳細は [`topics/02_cryptography/01_goals-and-primitives.md`](../../../topics/02_cryptography/01_goals-and-primitives.md) を参照。

---

## one-time key と many-time key

同じ鍵を何回使うかで、必要な暗号方式が変わる。

- **one-time key（1回限りの鍵）**: メール1通ごとに別の鍵を使う。鍵は1メッセージにしか使われない。
- **many-time key（多数回使う鍵）**: ディスク暗号化のように、同じ鍵で多数のファイルを暗号化する。

同じ鍵を繰り返し使う many-time key の方が攻撃者に手がかりを与えやすく、より強い暗号方式が必要になる。この区別は後の章（ストリーム暗号・ブロック暗号）で重要になる。

---

## 暗号にできないこと（3つの限界）

暗号は万能ではない。過信は危険だ。

1. **万能でない**: 暗号は通信路とデータを守るだけ。ソフトウェアのバグや、人をだますソーシャルエンジニアリングには無力。
2. **実装を誤ると無意味**: 正しい暗号でも組み込み方を間違えれば守れない。Wi-Fi の初期規格 **WEP** は暗号の使い方を誤り、容易に破られた（反面教師）。
3. **自作するな**: 標準化され査読された暗号（AES など）を使う。素人が設計した暗号はほぼ確実に破られる。

## 問題

**Q1.** 次のプロトコルと、それが主に守る対象を対応させよ。(a) HTTPS (b) WPA2 (c) ディスク暗号化

<details><summary>解答</summary>

(a) HTTPS = Web ブラウザとサーバ間の**通信**。(b) WPA2 = **無線 LAN（Wi-Fi）の通信**。(c) ディスク暗号化 = **保存されたファイル**（＝「今日の自分から明日の自分への通信」と同型）。

</details>

**Q2.** Kerckhoffs の原則によれば、暗号システムで秘密にすべきものは何か。アルゴリズムを秘密にする設計はなぜ危険か。

<details><summary>解答</summary>

秘密にすべきなのは**鍵だけ**。アルゴリズムは公開してよい。アルゴリズムの秘密に頼る設計（security through obscurity）は、(1) 公開レビューを受けておらず弱点が未検証、(2) リバースエンジニアリングで解析されると秘密が保てない、という理由で危険。

</details>

**Q3.** 次のうち one-time key の使い方はどれか。(a) 1通のメールごとに新しい鍵で暗号化する (b) 1つの鍵でディスク上の全ファイルを暗号化する

<details><summary>解答</summary>

(a)。メール1通ごとに別鍵を使うのが one-time key。(b) は同じ鍵を多数回使う many-time key。

</details>

**Q4.** 同僚が「社内向けに独自の秘密暗号アルゴリズムを設計した。非公開だから安全だ」と提案してきた。暗号の観点から正しい対応は何か。

<details><summary>解答</summary>

採用すべきでない。Kerckhoffs の原則に反し、査読されていない自作暗号は破られる可能性が高い。AES など標準化・査読済みの暗号を、正しい方法で使うよう勧めるのが正しい対応。

</details>
