# 02. 誕生日攻撃

> 親: [README](./README.md) ｜ 前: [衝突耐性の導入](./01_collision-resistance-intro.md) ｜ 次: (ビデオ2で追加予定) ｜ 出典: Crypto I ビデオ1 (8:09:03–末尾)

前ファイルで「衝突は存在するが見つけにくい」と述べた。では実際に衝突を探すと何回の計算が要るのか。ハッシュの中身に一切依存しない**汎用攻撃**が誕生日攻撃で、これがハッシュの出力長を直接決める。

---

## 汎用衝突攻撃

`n` bit 出力のハッシュ `H`(値域サイズ `B = 2^n`)に対し、中身を問わず効く手順:

```
1) ランダムなメッセージ m_1, …, m_k を約 k ≈ 2^(n/2) 個選ぶ
2) それぞれの H(m_i) を計算する
3) 同じ値になる 2 つ(衝突)があれば出力。なければ 1) に戻って繰り返す
```

素朴には全数 `2^n` 通りを調べないと衝突が出ないように思えるが、実際は `2^(n/2)` 個ほどで高確率に衝突が見つかる。その根拠が**誕生日パラドックス**(→ [02. XOR と誕生日パラドックス](../02_discrete-probability/02_xor-and-birthday-paradox.md))。1 回の試行(`2^(n/2)` 個サンプル)で衝突確率が約 1/2 なので、反復回数はごく少なくて済む。

---

## 誕生日パラドックスの確率評価(完結)

サンプル数 `n` 個、空間サイズ `B` の一様分布で「衝突が 1 つも起きない」確率を評価する。`i` 番目のサンプルが先行 `i−1` 個のどれとも衝突しない確率は `(1 − (i−1)/B)` なので:

```
Pr[衝突なし] = ∏_{i=1}^{n-1} (1 − i/B)
```

各因子に不等式 `1 − x ≤ e^(−x)` を使う:

```
∏_{i=1}^{n-1} (1 − i/B) ≤ ∏_{i=1}^{n-1} e^(−i/B)
                       = e^(−(1/B) · ∑_{i=1}^{n-1} i)
                       = e^(−n(n−1)/2B)
                       ≈ e^(−n^2/2B)
```

したがって衝突が起きる確率は:

```
Pr[衝突あり] ≥ 1 − e^(−n^2/2B)
```

`n = 1.2·√B` を代入すると `n^2/2B = 1.44B / 2B = 0.72`。ゆえに:

```
Pr[衝突あり] ≥ 1 − e^(−0.72) ≈ 1 − 0.487 ≈ 0.51   (> 1/2)
```

> **注記**: ビデオ1のトランスクリプトはこの評価の途中で終わっている。数値の締め(`1 − e^(−0.72) ≈ 0.51`、確かに 1/2 超)を明示しておく。結論は「約 `1.2√B` 個で衝突確率が 5 割を超える」。

---

## 出力長への含意

`B = 2^n` なら `√B = 2^(n/2)`。つまり **`n` bit 出力のハッシュは約 `2^(n/2)` 回で衝突する**:

| 出力長 `n` | 衝突に必要な計算量 `≈ 2^(n/2)` | 評価 |
|---|---|---|
| 128 bit | `2^64` | 現代の計算資源で到達しうる → **危険** |
| 256 bit | `2^128` | 実行不能 → **安全**(SHA-256 が標準の理由) |

衝突耐性を狙うなら、目標強度の **2 倍**の出力長が要る。128 bit 相当の強度が欲しければ 256 bit 出力にする。これが SHA-256 が実務標準である理由。

衝突確率 `1 − e^(−n^2/2B)` の立ち上がりは急峻で、`√B` 付近で一気に 1 に近づく:

```
Pr[衝突]
 1.0 |                    ●●●●●●●   (≈ 2√B 以降ほぼ 1)
     |              ●
 0.5 |         ●                (≈ 1.2√B で 0.5 超)
     |      ●
 0.0 |●●______________________ サンプル数 n
     0     √B    2√B
```

続き(Merkle–Damgård 構成による任意長ハッシュの作り方、鍵付きの HMAC)はビデオ2で扱う。

## 問題

**Q1.** `1 − e^(−0.72)` を評価し、`n = 1.2√B` 個のサンプルでの衝突確率が 1/2 を超えることを確認せよ。

<details><summary>解答</summary>

`e^(−0.72) ≈ 0.487` なので `1 − 0.487 ≈ 0.51`。`0.51 > 0.5` より、約 `1.2√B` 個のサンプルで衝突確率が 1/2 を超える。

</details>

**Q2.** SHA-256(出力 256 bit)に対する誕生日攻撃の計算量はおよそいくらか。

<details><summary>解答</summary>

`2^(256/2) = 2^128` 回のハッシュ計算。原像を狙う総当たり `2^256` よりはるかに小さいが、`2^128` 自体が実行不能なので SHA-256 の衝突耐性は保たれる。

</details>

**Q3.** タグ長 `n` bit の MAC と出力 `n` bit のハッシュで、「安全に使える `n`」が異なるのはなぜか。

<details><summary>解答</summary>

MAC のタグは鍵を知らないと計算できないため、攻撃者は当てずっぽうで偽造するしかなく成功確率は `1/2^n`(全数 `2^n` オーダー)。一方ハッシュは鍵なしで誰でも計算できるので、攻撃者は誕生日攻撃で `2^(n/2)` に落とせる。同じ `n` でもハッシュの方が要求が厳しく、衝突耐性には倍の出力長が要る。

</details>

**Q4.** モジュール06 の CBC-MAC に対する `√|X|` 攻撃(内部の中間値の衝突を突く)と、本ファイルの誕生日攻撃の関係を述べよ。

<details><summary>解答</summary>

どちらも同じ誕生日パラドックスの帰結。CBC-MAC は約 `√|X| = 2^(n/2)` 個のメッセージを問い合わせると内部の中間値(タグ)が衝突し、そこから偽造できる。ハッシュの衝突探索と同じく「`n` bit 空間は `2^(n/2)` で衝突する」ことが安全性境界を決める。→ [06. メッセージ完全性](../06_message-integrity/README.md)

</details>
